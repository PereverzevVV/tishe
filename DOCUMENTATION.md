# Tishe — документация проекта

**Tishe** (до 2026-10-09 — Handy Plus) — это доработанная версия [Handy](https://github.com/cjpais/Handy) 0.9.8, настольного приложения для диктовки (Tauri 2: Rust + React). Всё, что умеет Handy, сохранено: голосовой ввод по горячей клавише, локальные модели, история, пост-обработка через LLM. Добавлен раздел **«Расшифровка»** (раньше вкладка «Файл»): расшифровка готовых аудио- и видеозаписей любой длины в документ Word или Markdown, в том числе очередью из нескольких файлов. Для редактуры текста есть **встроенная локальная нейросеть**, которая работает без интернета и без установки Ollama.

С 2026-10-09 программа называется **Tishe**: так подписаны окно, трей, уведомления и установщик; с выпуска 2026-10-15 папки данных называются `io.github.pereverzevvv.tishe`, а программа — `tishe.exe`; данные из прежней `com.handyplus.app` переносятся сами (§2). Окно собрано заново по проекту интерфейса **Tishe** (папка `docs/`: аудит, архитектура разделов и взаимодействия, визуальная система v3). Разделы окна теперь называются по сценариям — «Расшифровка», «Диктовка», «История» — и по ресурсам — «Модели», «Нейросеть», «Приложение». Где теперь какая настройка, — в §3.0.

История изменений по датам — в [CHANGELOG.md](CHANGELOG.md).

## 2. Установка и переход со старого Handy

### Установка

Запустите `Tishe_0.9.8_x64-setup.exe`. Установщик не подписан сертификатом, поэтому Windows SmartScreen покажет предупреждение: «Подробнее» → «Выполнить в любом случае».

**Переход с Handy Plus на Tishe.** Это одна и та же программа под новым именем. Установщик Tishe находит установленный Handy Plus, тихо запускает его деинсталлятор (без галочки «удалить данные»), убирает оставшуюся папку `%LOCALAPPDATA%\Handy Plus\`, ярлыки и автозапуск под старым именем и ставит Tishe в `%LOCALAPPDATA%\Tishe\`. Настройки, модели, история, записи и результаты расшифровки подхватываются без ручного переноса. Если Handy Plus запущен, установщик сначала попросит его закрыть.

**Новый идентификатор (выпуск 2026-10-15).** До публичного выпуска программа хранила данные в папках `com.handyplus.app` и называлась `handy.exe`. Теперь идентификатор `io.github.pereverzevvv.tishe`, а программа — `tishe.exe`. При первом запуске новой версии Tishe сама переносит всё из `%APPDATA%\com.handyplus.app\` и `%LOCALAPPDATA%\com.handyplus.app\` (настройки, историю, записи, модели нейросети и голосов, журналы, состояние окна) в новые папки. Перенос — переименование на том же диске, поэтому даже гигабайтные модели переезжают мгновенно; в новой папке ничего не перезаписывается. Пустая старая папка удаляется. Если что-то перенести не удалось (например, старая версия ещё запущена), оно остаётся на месте, а перенос повторится при следующем запуске (§5.25). Установщик закрывает запущенный `handy.exe` из папки Tishe и заменяет его на `tishe.exe`; ярлыки и автозапуск переписываются на новое имя.

| ---------------------------------- | ----------------------------------------------------- |
| Программа                          | `%LOCALAPPDATA%\Tishe\` (до 2026-10 — `Handy Plus\`)  |
| Настройки, модели, история, записи | `%APPDATA%\io.github.pereverzevvv.tishe\` (до 2026-10-15 — `com.handyplus.app`) |
| Журналы (логи)                     | `%LOCALAPPDATA%\io.github.pereverzevvv.tishe\logs\` |
| Настройки «Расшифровки»            | `%APPDATA%\io.github.pereverzevvv.tishe\file_transcription.json` |
| Готовые документы в списке         | `%APPDATA%\io.github.pereverzevvv.tishe\file_results.json` |
| Модели локальной нейросети         | `%APPDATA%\io.github.pereverzevvv.tishe\llm-models\` |
| Модели разделения по говорящим     | `%APPDATA%\io.github.pereverzevvv.tishe\diarization-models\` |
| Движок локальной нейросети         | `%LOCALAPPDATA%\Tishe\llama\`                         |
| ffmpeg (сборка под LGPL)           | `%LOCALAPPDATA%\Tishe\ffmpeg\` (с лицензией и ссылкой на исходники) |
| Лицензии сторонних компонентов     | `%LOCALAPPDATA%\Tishe\licenses\THIRD_PARTY_NOTICES.txt` |

### Перенос данных из старого Handy

Данные старого Handy (`%APPDATA%\com.pais.handy\`) **скопированы** в `%APPDATA%\com.handyplus.app\` (с 2026-10-15 Tishe переносит эту папку в свою, см. выше): скачанные модели (Whisper Large v3, GigaAM v3), настройки (горячие клавиши, микрофон, выбранная модель, ключи LLM, словарь), история и записи. Оригинальная папка не менялась.

После удаления старого Handy его папку `%APPDATA%\com.pais.handy\` можно удалить вручную: это освободит ~1,3 ГБ, Tishe она уже не нужна. Модели, скачанные через каталог (формат GGUF), лежат в общем кэше `%USERPROFILE%\.cache\huggingface`. Его удалять не нужно.

### Важно

Два приложения с одной горячей клавишей (Ctrl+Space) одновременно работать не могут: клавишу получит тот, кто запустился первым. Удалите старый Handy («Параметры → Приложения → Handy → Удалить») или хотя бы закройте его и уберите из автозапуска.

### ffmpeg

Для чтения аудио и видео нужен ffmpeg. С выпуска 2026-10-15 он входит в установщик: папка `ffmpeg\` рядом с `tishe.exe`, сборка BtbN под LGPL v3 (n8.1.3), там же её лицензия `LICENSE.txt` и ссылки на исходный код `SOURCE.txt` (§5.25). Ставить ffmpeg отдельно больше не нужно.

Tishe ищет `ffmpeg.exe` в таком порядке: `ffmpeg\` рядом со своим exe → рядом с exe → в `PATH` → в папке пакета winget (`%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg*\*\bin`). Последние варианты — запасные: для сборки без ffmpeg и для разработки. Если ffmpeg не найден, вкладка покажет красное предупреждение с командой `winget install Gyan.FFmpeg`.

## 3. Как пользоваться окном и «Расшифровкой»

### 3.0. Разделы окна и где теперь какая настройка

Слева сайдбар с логотипом и словом «Tishe» и разделами, снизу строка состояния. С 2026-10-18 разделы называются по тому, что они делают: «Распознавание» — модели, которые превращают речь в текст (раньше «Модели»), «Редактура» — нейросеть, которая исправляет текст (раньше «Нейросеть»); внутри всё как было (§5.27). Выбранный раздел выделен серой заливкой и жирным шрифтом. Порядок разделов и правило, по которому каждая настройка попала в свой раздел, такие: настройка одного сценария живёт в этом сценарии, а настройка общего движка — на странице ресурса, в сценарии же показана строкой «Распознавание: … · Изменить».

| Раздел | Что там |
| --- | --- |
| **Расшифровка** | Зона файлов (можно перетащить записи на окно), один список очереди и результатов, «Рецепт» (где распознавать, говорящие, редактура нейросетью, итог «Результат», какая модель распознаёт), складка «Дополнительно» (длина части, поля облака, модель голосов, инструкция для файлов, документ: формат, папка, тайм-коды, заминки, замечания; скрипт событий), закреплённая панель с кнопкой «Расшифровать N файлов» |
| **Диктовка** | Статус и клавиша; «Клавиши»: диктовка, поведение клавиши, отмена, «Диктовка с редактурой — вторая клавиша» (её клавиша и инструкция появляются под ней); «Звук»: микрофон, канал, глушить звук, звуковой отклик (тема, устройство вывода и громкость — под ним); «Дополнительно»: вставка текста, текст диктовки (слова-паразиты), индикатор записи, микрофон и запись, библиотека инструкций; «Если что-то не работает»: задержки вставки, надёжная вставка, дописывание после отпускания, порог удержания (только в режиме «Автоматически») |
| **Встречи · скоро** | Честная страница о будущей записи встреч и переход к «Расшифровке» |
| **История** | Строка «Хранятся последние N диктовок · Изменить» (под ней размер и срок хранения), «Открыть папку записей», диктовки по дням: копировать, прослушать, «После редактуры / Исходный», в «⋯» — «Сохранить», «Распознать заново», «Удалить» |
| **Распознавание** (до 2026-10-18 — «Модели») | Активная модель распознавания (смена, ⚙), язык распознавания и перевод на английский (если модель умеет), «Дополнительно»: очистка текста внутри модели (свои слова, порог исправления, китайская письменность) и выгрузка из памяти; каталог: «Ваши модели», «Рекомендуем», «Все модели» с поиском и фильтрами. «Скачать» и «Использовать» — отдельные кнопки |
| **Редактура** (до 2026-10-18 — «Нейросеть») | Для чего используется, «Где работает нейросеть»: на этом компьютере (встроенная, рекомендуется), свой сервер, облачный сервис; под выбором — то, что нужно этому варианту: каталог встроенных моделей, адрес и модель сервера или поставщик, ключ и модель сервиса; «Дополнительно»: выгрузка из памяти |
| **Приложение** | Запуск и трей (с подсказкой, как держать значок на виду), вид (тема «Как в системе / Светлая / Тёмная», язык интерфейса), уведомления о готовой расшифровке, обновления (проверка новой версии на GitHub, §5.8), экспериментальные функции (за своим переключателем) |
| **Что дальше** | Что такое Tishe и Private Memory, что уже умеет, план следующих версий (запись встреч, итоги, поиск, заметки и ассистенты) без дат, кнопки «Следить на GitHub» и «Сообщить о проблеме или идее» |
| **О программе** | Версия и дата выпуска («Tishe 0.9.8, выпуск 2026.10.17»), «Что нового», ссылка на репозиторий Tishe, происхождение от Handy, «Лицензии» (открывает `THIRD_PARTY_NOTICES.txt`), благодарности, папки данных и журналов |

**Как ходить между разделами.** Ссылки «Изменить», «Другие варианты», «Выбрать» открывают нужный раздел, раскрывают складку, прокручивают к группе, на полторы секунды подсвечивают её и ставят на неё фокус. Вверху появляется строка «← Назад к «Расшифровке»»; то же делают Alt+← и кнопка «назад» мыши. Складки помнят, открыты они или нет, и показывают «изменено: N», если внутри что-то отличается от стандартного. Внутри складки у такой настройки рядом с названием метка «изменено» и кнопка ↺ «Вернуть стандартное». У «Своих слов» и у размера и срока хранения истории кнопки сброса нет, только метка: сброс удалил бы слова или старые диктовки.

**Узкое окно и крупный масштаб.** Ctrl + «+», Ctrl + «−», Ctrl + 0 и Ctrl + колесо мыши меняют масштаб окна. Когда рабочей области остаётся меньше 520 точек (минимальное окно с масштабом от ~135 %), сайдбар становится полоской значков шириной 56, подписи разделов — в подсказках при наведении, а поля колонки уменьшаются с 24 до 16. При 200 % в минимальном окне колонке остаётся 270 px вместо 136.

**Перетаскивание файлов.** Пока файлы над окном, рабочая область закрыта пунктирной целью с тем, что будет: «Отпустите, чтобы добавить · «лекция.mp3» встанет в очередь расшифровки», «3 записи встанут в очередь», «Ещё 2 файла будут пропущены: это не аудио и не видео», «уже стоит в очереди», а если подходящих нет — «Эти файлы не подойдут». Синей рамки нет: цель нейтральная, как пунктирная зона на странице.

**Трей и уведомления.** Подсказка значка в покое: «Tishe · Диктовка: Ctrl+Space · модель»; во время расшифровки — «Расшифровка: файл 1 из 3 · 47 %», а значок — «работаю»; после конца, пока «Расшифровка» не открыта, — «Расшифровка готова: 3 файла». Во время расшифровки в меню трея «Модель ▸» первой строкой пишет «Пока идёт расшифровка, модель не меняется», модели и «Выгрузить модель» неактивны, а «Выход» сначала показывает окно с вопросом «Выйти из Tishe?» (фокус на «Остаться»). Если окно скрыто или не в фокусе, в конце очереди приходит одно уведомление Windows: «Расшифровка готова · лекция.docx · Открыть», «Расшифровка готова: 3 файла», «Готово 2 из 3 · 1 с ошибкой» или «Расшифровка не удалась». Нажатие открывает окно на строке результата (или первой ошибки), кнопка «Открыть» — сам документ. Если закрыть окно крестиком во время расшифровки, один раз в жизни программы приходит «Tishe работает в фоне». Выключается в «Приложение → Уведомления».

**Сообщения у курсора.** Индикатор записи сообщает о сбое диктовки на 4–6 секунд и не забирает фокус: «Не удалось вставить. Текст сохранён в «Истории»», «Вставлено без редактуры: нейросеть не готова», «Микрофон не найден», «Нет доступа к микрофону» — с кнопкой «Что делать», которая открывает окно на нужной группе («Если что-то не работает → Текст не вставляется», «Нейросеть», «Звук»). Пока модель занята расшифровкой файла, вместо «Распознаю…» написано «Модель занята расшифровкой файла — диктовка задержится». Если индикатор выключен, сообщений нет, и строка под настройкой это говорит.

**Клавиша занята.** В экспериментальном режиме системных сочетаний (Windows `RegisterHotKey`) клавишу может перехватить другая программа. Тогда статус «Диктовки» — «Диктовка не запускается: клавиша занята · Сменить клавишу», а при выборе занятой клавиши — «Эту клавишу уже заняла другая программа». В обычном режиме (перехватчик handy-keys, по умолчанию на Windows) клавиша не бывает «занята»: программа слышит её, даже если её зарегистрировал кто-то ещё.

**Первый запуск.** Экран стоит посередине окна при любом размере. На окне шире 900 точек он в две колонки: слева «Добро пожаловать в Tishe», что программа умеет (расшифровка записей в Word, диктовка в любой программе, всё остаётся на компьютере), три шага настройки с отметкой, где вы сейчас, и подпись «Виктор Переверзев · на основе Handy»; справа — сам шаг. На узком окне слева остаются только логотип и «Шаг 2 из 3».

1. **Разрешения.** На Windows обычно проходят сами. Если доступ к микрофону выключен в Windows — кнопка «Открыть настройки системы» и ссылка «Продолжить без микрофона»: микрофон нужен только для диктовки, расшифровка файлов работает и без него.
2. **«На каком языке ваши записи?»** «Русский» — GigaAM v3 E2E-CTC (только русский), «English» — Parakeet Unified EN, «Другой европейский язык» — Parakeet Ultra (25 языков Европы), «Другой язык» — Qwen3-ASR 0.6B (30 языков, в том числе китайский, японский, арабский, турецкий, хинди); если язык Windows не знает ни Ultra, ни Qwen (иврит, казахский…), четвёртая карточка предлагает Whisper Large v3. У каждой карточки кружок выбора, ограничение и размер. Заранее выбрана карточка языка Windows, а если модель уже лежит на диске — она («Использовать …»). Клик только выбирает; скачивание начинает большая кнопка, которая называет модель и размер: «Скачать GigaAM v3 · 241 МБ», под ней — «Скачивается один раз, потом работает без интернета». «Выбрать другую модель» раскрывает каталог на месте.
3. **Скачивание** — процент, «N из M» и скорость; ниже — «Пока качается — как это работает»: как диктовать (с вашей клавишей), как расшифровать запись, где включается редактура. Кнопки «Отменить» и «Открыть Tishe, не дожидаясь» — скачивание продолжится, а его ход будет виден в «Быстром старте». При ошибке — «Повторить» или «Выбрать другую модель».

**«Быстрый старт».** После первого запуска «Расшифровка» начинается со списка из трёх шагов, как в приложениях, которые встречают нового человека посередине главного экрана:
1. *Скачайте модель распознавания* — язык записей, «Скачать {размер}» и ход скачивания прямо здесь (если открыли Tishe, не дожидаясь конца, — тут виден прогресс);
2. *Попробуйте диктовку* — где поставить курсор и какую клавишу удерживать, «Сменить клавишу»;
3. *Расшифруйте запись* — «Добавить файлы…» (или перетащить запись в окно);

и отдельно *Редактура нейросетью · необязательно* — «Скачать {размер}» или «Другие варианты». Шаг отмечается галочкой, когда это действительно произошло: модель стала активной, в «Истории» появилась диктовка, расшифрован первый файл. Когда три шага сделаны — «Всё готово» и «Закрыть». «Скрыть» убирает список насовсем; все настройки остаются в разделах слева. Тем, кто обновился с прежней версии, список не показывается.

**Если модели распознавания нет** (удалили, или «Быстрый старт» скрыт), на «Расшифровке», «Диктовке» и «Моделях» вместо красной строки стоит карточка «Скачайте модель распознавания»: язык записей, рекомендованная модель с размером, «Скачать» и прогресс в самой карточке, «Все модели». Записи можно добавить в очередь заранее — внизу будет «Сначала скачайте модель распознавания» или «Модель распознавания качается · N %». Если модель уже на диске, но не выбрана (например, перенесена из Handy), карточка предлагает «Использовать …».

**Редактура без нейросети.** Если включить «Редактуру нейросетью» в рецепте или «Диктовку с редактурой» в «Диктовке», а нейросети ещё нет, открывается окно «Для редактуры нужна нейросеть»: что она делает, какую модель рекомендуем (Gemma 4 E4B, 2,9 ГБ на диске, около 6,3 ГБ памяти), кнопка «Скачать 2,9 ГБ и включить» и ссылка «Свой сервер или облако». То же окно — если выбран облачный сервис, но ключ к нему так и не вписан: «Скачать и включить» заодно переключает «Где работает нейросеть» на этот компьютер. Если подходящая модель уже скачана, вместо скачивания — «Включить редактуру». Если выбран свой сервер или облачный сервис, но не хватает ключа, адреса или названия модели, окно говорит, чего именно, и кнопкой «Включить и настроить» ведёт в «Нейросеть». Если редактура уже включена, а нейросеть не готова, «Расшифровать» ждёт её, а внизу — причина и действия: «Скачать 2,9 ГБ» (или «Изменить») и «Без редактуры».

**Широкое окно** (от 1280 точек по ширине, например развёрнутое на весь экран 1920 × 1080): страница расширяется до 1080 и у всех разделов начинается от одного левого края. Правило одно на все разделы: главное слева, дополнительное справа.

| Раздел | Слева | Справа |
| --- | --- | --- |
| Расшифровка | зона файлов и список | «Рецепт» и «Дополнительно» |
| Диктовка | состояние, клавиши, звук | «Дополнительно», «Если что-то не работает» |
| История | диктовки | срок хранения и «Открыть папку записей» |
| Распознавание | активная модель, язык | «Дополнительно»; каталог ниже на всю ширину, в две колонки |
| Редактура | где работает, сервис или модель | «Используется для» |
| Приложение | запуск и трей, вид | уведомления, обновления, экспериментальные функции |
| Что дальше | что такое Tishe и планы | «Бесплатно и с открытым кодом» |
| О программе | версия, о проекте | благодарности, папки |

Более короткая колонка остаётся на месте, пока прокручиваете другую: например, список файлов виден, пока листаете длинный рецепт с раскрытым «Дополнительно». Пустая зона «Перетащите запись сюда» занимает высоту рядом с рецептом, но не выше окна, так что надпись и кнопка всегда видны. Формы настроек и текст не шире 640: длинные строки читать труднее. Кнопка «Расшифровать» стоит под правым краем содержимого, а не у края экрана. На окне уже 1280 всё как раньше, одной колонкой (§5.26).

**Строка состояния** внизу видна на любой странице: модель распознавания (точка — в памяти, пустой кружок — нет, крутилка — загружается; нажатие открывает список скачанных моделей, во время расшифровки он заблокирован), идущая расшифровка («файл 1 из 2 · 47 %», нажатие ведёт к строке файла), скачивания моделей и нейросети, «Вышла версия 2026.10.20», если на GitHub есть выпуск новее (нажатие открывает его страницу), версия.

### Шаги на «Расшифровке»

1. **Добавить записи**: перетащите файлы на окно (с любой страницы — откроется «Расшифровка») или нажмите «Добавить файлы…». Подходят mp3, wav, m4a, aac, ogg, opus, flac, wma, webm, mkv, mp4, m4v, mov, avi, wmv; файлы другого типа не добавляются, под зоной на 6 секунд появляется строка с их именами. Из видео берётся первая звуковая дорожка.
2. **Рецепт.** «Где распознавать»: «На этом компьютере» (модель из раздела «Распознавание», офлайн и бесплатно) или «В облаке» (поставщик и ключ появляются прямо под выбором, адрес, модель и язык — в «Дополнительно → Распознавание»; строка «Звук уйдёт в …» видна и в рецепте, и в панели). «Говорящие» — документ станет стенограммой (§3.3); если модели голосов нет, под переключателем строка «Нужна модель голосов · Скачать». «Редактура нейросетью» — самый долгий этап, ≈ 15–35 минут на час записи на процессоре (§3.1); под переключателем строка готовности: «Нейросеть готова · …», «Нужна нейросеть · Скачать», «Текст уйдёт в …» или «Нужен ключ …». «Результат: Word · рядом с записью · Изменить» раскрывает «Дополнительно → Документ».
3. **Дополнительно** (редко): длина части (по умолчанию 29 мин, от 2 до 180), модель голосов, инструкция для файлов (пусто — встроенная на языке записи; порядок: это поле, затем ⚙ модели, затем встроенная, §5.17), «Добавить исходную расшифровку», формат, папка, тайм-коды, «Убирать заминки», «Замечания обработки», скрипт событий (§3.2).
4. **«Расшифровать N файлов»** в панели внизу. Если запустить нельзя, слева в панели написана первая причина и действие, которое её снимает («Сначала выберите модель распознавания · Выбрать», «Нужен ключ OpenAI · Изменить», «Нужна модель голосов · Скачать»). Пока идёт работа, рецепт заблокирован (новые файлы пойдут с теми же параметрами), у текущего файла видны этап, номер части, процент и примерный остаток времени, в сайдбаре у «Расшифровки» крутится индикатор, в строке состояния — «файл 1 из 2 · 47 %». Можно уходить на другие страницы.
5. **Готово.** В панели на 6 секунд «Готово: N файлов»; если окно было скрыто или не в фокусе — уведомление Windows (§3.0). У готового файла нет значка: дата, длительность, число частей и знаков, состав рецепта, путь к документу, кнопка «Открыть» и «⋯» («Показать в папке», «Убрать из списка»). Если были замечания обработки, под строкой «N замечаний обработки» — по нажатию раскрывается список. Если окно было на другой странице или скрыто, у «Расшифровки» в сайдбаре появляется синяя точка до первого просмотра.
6. **«Отменить»** спрашивает подтверждение («Остановить расшифровку?»: готовые файлы сохранены, текущий и ожидающие придётся запустить заново). Ошибка в одном файле не останавливает очередь: у файла красный кружок «!» и причина. Повторное «Расшифровать» обработает всё, что не готово. «Убрать из списка» и «Убрать готовые» можно вернуть кнопкой «Вернуть» в уведомлении; файлы на диске не трогаются.

Все параметры рецепта и «Дополнительно» общие для очереди и запоминаются между запусками (`file_transcription.json`). Готовые документы тоже: последние 50 хранятся в `file_results.json` и видны после перезапуска; внизу полного списка строка «Хранятся последние 50 результатов. Документы на диске не удаляются». При открытии раздела и при «Открыть» программа проверяет, на месте ли документ; если его переместили, удалили или отключили диск, строка пишет «Документ не найден» и предлагает только «Убрать из списка». Ожидающие и отменённые файлы между запусками не хранятся.

### 3.1. Локальная нейросеть

Поставщик LLM **«Локальная нейросеть (встроенная)»** выбирается в разделе «Редактура» и действует и на «Расшифровку», и в разделе «Пост-обработка». Ничего ставить не нужно: движок (llama.cpp, ~25 МБ) уже входит в установщик. Пока пользователь сам не выберет этого поставщика и не скачает модель, нейросеть ничего не занимает.

Семь моделей. Все помещаются в ноутбук с 16 ГБ памяти и работают на процессоре. Скорость и качество замерены на стенде 2026-10-06 на русском интервью (§9.3):

У GigaChat и Qwen3.5 9B стоит пометка «не проверена»: их не скачивали. Совместимость проверена по заголовку файла: архитектуры `deepseek2` и `qwen35` встроенный llama.cpp поддерживает. GigaChat — смесь экспертов: из 10 млрд параметров на токен работают 1,8 млрд, поэтому она должна быть быстрее Qwen 4B, но памяти занимает больше.

**Убраны после стенда:**
- Qwen3.5 2B и Qwen3.5 2B MTP, MiniCPM5 2B — возвращают текст почти без изменений;
- LFM2.5 2.6B и 8B-A1B — рассуждают вместо ответа и выбрасывают предложения (§9.3).

Если одна из них была выбрана, программа при следующем запуске нейросети сама переключится на скачанную модель из оставшихся: сначала Gemma ⚡, затем остальные с ускорителем. Файлы убранных моделей остаются на диске, пока их не удалить вручную из `%APPDATA%\io.github.pereverzevvv.tishe\llm-models\`:
- `Qwen3.5-2B-Q4_K_M.gguf` (1,3 ГБ);
- папки `qwen3.5-2b-mtp`, `minicpm5-2b`, `lfm2.5-2.6b`, `lfm2.5-8b-a1b` (1,3 / 2,2 / 2,0 / 5,5 ГБ).

Как это работает:

- Модель скачивается кнопкой «Скачать» (с Hugging Face, с проверкой SHA-256). Обрыв связи не страшен: загрузка до 6 раз сама продолжается с места обрыва. «Отменить» удаляет недокачанный файл.
- Модель выбирается щелчком по строке. Первая скачанная модель выбирается сама. Корзина удаляет модель с диска.
- Нейросеть **запускается сама** при первом обращении (3–7 с) и **выгружается сама** по настройке «Выгружать из памяти»: сразу после обработки, через 2 / 5 (по умолчанию) / 15 мин простоя или никогда. Пока идёт очередь файлов, она не выгружается между файлами. Кнопка «Выгрузить сейчас» освобождает память немедленно. При смене модели сервер перезапускается сам.
- Режим «размышлений» (у Qwen3.5 и Gemma 4 он включён по умолчанию) отключён флагом `--reasoning off`: для редактуры он только тратит время.
- Если важна дословность, включайте «Добавить исходную расшифровку».

**Замер на реальной записи (2026-10-06, Ryzen 5 7530U).** Интервью 64 мин, два человека, с разделением по говорящим. Цифры выше получены на коротком тексте без говорящих, на длинном разговоре они другие:

| Связка | Всего | Из них LLM |
| ------ | ----- | ---------- |
| Qwen3-ASR 1.7B + Gemma 4 E4B | 50 мин | ~30 мин (оценка) |
| GigaAM v3 E2E-CTC + Gemma 4 E4B | 42 мин | ~32–35 мин (оценка) |
| GigaAM v3 E2E-CTC + Qwen3.5 2B | 21 мин | 14,5 мин (по журналу) |

- Реальная скорость: Gemma ~23 знака/с, Qwen3.5 2B ~50 знаков/с.
- **Qwen3.5 2B на разговоре почти ничего не исправила**: ~77% текста осталось как было. Отчасти она возвращает текст без изменений, отчасти добавляет лишнюю метку «Спикер», и тогда весь кусок откатывается к исходному.
- Лучшее качество — у Qwen3-ASR + Gemma.

#### Модели с ускорителем (добавлены 2026-10-06)

Три модели в списке — с **ускорителем** (значок ⚡). Как работает ускоритель и почему его взяли, рассказано в §5.16. Коротко: маленькая модель-помощник угадывает несколько слов вперёд, основная модель их проверяет. У Gemma текст получается тот же, что без ускорителя, только быстрее: на этом процессоре в 1,2–1,3 раза. У Qwen MTP-файл — другая сборка весов, поэтому и текст другой (§9.3).

| Карточка | Ускоритель |
| --- | --- |
| **Сбалансированная ⚡** (Qwen3.5 4B MTP) | встроен в файл |
| **Gemma лёгкая ⚡** (Gemma 4 E2B QAT) | MTP, `amaranus/Gemma-4-E2B-it-qat-assistant-MTP-Q8_0-GGUF` (+98 МБ) |
| **Gemma ⚡** (Gemma 4 E4B QAT) | MTP, `amaranus/Gemma-4-E4B-it-qat-assistant-MTP-Q8_0-GGUF` (+99 МБ) |

- Модель и её ускоритель скачиваются одной кнопкой, с одной полосой прогресса. Корзина удаляет оба файла.
- У каждой модели с ускорителем своя папка `llm-models\<id>\`. Модели без ускорителя лежат прямо в `llm-models\`.
- Как ускоритель запускается, видно в `llama-server.log`: строка `draft acceptance = …` показывает, какая доля угаданных слов принята.

**Первая проверка (2026-10-06, Ryzen 5 7530U).** Скачан только ускоритель Gemma E4B QAT (98 МБ, SHA-256 совпал), а основная модель была обычная, не QAT, из прежней карточки «Gemma». Короткая фраза из интервью, 49 токенов ответа:

| | Скорость ответа | Принято угаданных |
| --- | --- | --- |
| Без ускорителя | 10,3 токена/с | — |
| С ускорителем, 2 слова вперёд | 10,2 токена/с | 61% (27 из 44) |

Ускоритель загрузился и работает, ответ правильный. Но на этой фразе выигрыша нет. Причина может быть в непарной основной модели, в слишком коротком тексте или в том, что на процессоре проверка угаданного стоит дороже, чем на видеокарте. Честный ответ даст только замер на эталоне с правильными парами.

**Итог стенда (2026-10-06, 10 моделей, 3 повтора, подробно в §9.3).**

### 3.1.1. Окно ⚙ «Параметры» у моделей

У каждой скачанной модели есть кнопка «Параметры»: у моделей распознавания — в разделе «Распознавание», у встроенной нейросети — значок ⚙ на её карточке в «Пост-обработке». Изменения сохраняются сразу. В полях всегда стоят значения, которые сейчас действуют, и под каждым написано стандартное значение. У изменённого поля есть кнопка возврата, внизу — «Сбросить к стандартным».

**Встроенная нейросеть:**

| Параметр | Стандартно | Что меняет |
| --- | --- | --- |
| Инструкция для русского текста | встроенная (у Gemma 4 E4B и E4B QAT — с правилом осторожности, §9.4) | поле заполнено встроенным текстом; измените — будет своя, сотрите — вернётся встроенная |
| Инструкция для английского текста | встроенная | то же |
| Температура | 0,2 | 0–1,5; при 0,8 Gemma выдумывала слова (§5.15) |
| Размер куска, знаков | 3000 | 1000–8000 |
| Контекст, токенов | 8192 | 4096–32768; должен вмещать кусок и ответ, иначе значение не сохранится |
| Лимит ответа, токенов | 3072 | 512–8192 |
| Потоки процессора для ответа | авто — по одному на ядро | чтение текста всегда идёт на всех потоках (§5.10) |

Для языков кроме русского и английского — встроенная английская с названием языка. Температура, контекст, лимит и потоки — параметры запуска: запущенная нейросеть перезапускается с ними перед следующей задачей, а не посреди текущей.

| Устройство | как в настройке ускорения | «Только процессор». Только для моделей transcribe-cpp (Whisper, Qwen3-ASR, GigaAM GGUF…); действует и для диктовки |

### 3.2. Прогресс в других программах (скрипт событий)

Расшифровка длинной записи на локальной модели может идти полчаса. Чтобы не держать окно Tishe открытым, прогресс можно передавать в другую программу.

1. **«Файл» → «Интеграции» → «Скрипт событий» → «Выбрать…»**: программа или скрипт (`.exe`, `.ps1`, `.bat`, `.cmd`).
2. **«Проверить»** отправляет тестовое событие. Зелёная надпись — скрипт его получил, красная — текст ошибки.
3. **«Как часто сообщать о прогрессе»** — не чаще одного раза за столько секунд, по умолчанию 10 (от 1 до 600). Смена этапа или части, начало и конец отправляются сразу.
4. Дальше при каждом файле Tishe сам запускает скрипт: в начале, по ходу и в конце, с успехом, ошибкой или отменой.

Готовые примеры лежат в папке `examples/event-scripts/` репозитория:

- `coucou.ps1` — на «острове» [Coucou](https://github.com/Louis-CFM/coucou) имя файла и под ним одна строка, которая обновляется на месте: «Распознавание: часть 2 из 3 · 47% · осталось ~12 мин»; в конце звук и «Готово». Нужен Coucou для Windows 0.2.0 со сборкой, понимающей событие `Progress`. В настройках Coucou агент появляется в разделе «Custom agents», там его можно выключить или проверить;
- `toast.ps1` — уведомление Windows, когда файл готов или упал;
- `log.ps1` — журнал всех событий в `%TEMP%\tishe-events.log` (до 2026-10-12 — `handy-plus-events.log`).

Свой скрипт пишется по образцу: формат события описан в §7 и в `examples/event-scripts/README.md`. Кнопка сброса выключает функцию.

### 3.3. Разделение по говорящим

Программа сама определяет, где говорит другой человек, и размечает текст как стенограмму. Это называется диаризацией. Работает на этом компьютере, без интернета; запись никуда не отправляется.

1. **«Файл» → «Говорящие» → «Разделить по говорящим»**.
2. **«Скачать»** у модели голосов. Скачивается один раз: ~33 МБ для WeSpeaker (рекомендуем) или ~46 МБ для 3D-Speaker. Сюда входит общая для обеих модель сегментации (6 МБ). Скачанную модель можно выбрать щелчком или удалить корзиной.
3. **«Сколько человек на записи»**: «Определить автоматически» или точное число от 2 до 8. Если знаете, сколько людей говорит, укажите: так надёжнее.
4. «Расшифровать» как обычно. В строке прогресса появится этап «Определение говорящих…».

Результат с тайм-кодами:

```markdown
**[00:00:00] Спикер 1:** Для того чтобы просто понимать, как это работает…

**[00:00:25] Спикер 2:** Значит, рост ставки будем прогнозировать…
```

Тайм-коды ставятся и в обработанном нейросетью тексте. Без тайм-кодов — `**Спикер 1:** …`. Подряд идущие фразы одного человека собираются в один абзац. Длинный монолог делится на абзацы, но метка ставится только у первого. Если реплика продолжается в следующей части записи, метку ещё раз не ставят. В Word метка спикера — жирным, тайм-код — серым.

- Номер спикера сквозной на весь файл: «Спикер 1» в первой и в третьей части — один и тот же человек.
- Спикеры безымянные. Имена можно проставить заменой в документе («Найти и заменить» «Спикер 1» → «Анна»).
- С LLM нейросети передаётся текст с метками и строгое правило их не трогать. Если нейросеть всё же потеряла или добавила метку, в документ идёт исходный текст этого куска, а в результате появляется предупреждение.
- С облачным распознаванием работает только у моделей с тайм-кодами: `whisper-1` у OpenAI и whisper-модели у Groq. У `gpt-4o-transcribe` тайм-кодов нет. Вкладка предупредит об этом, этап «Говорящие» будет пропущен (время на него не тратится), а в результате появится одно предупреждение.
- Если нейросеть вынесла метку «Спикер 1:» на отдельную строку, метка приклеивается к следующему абзацу.

Время: на этом компьютере (Ryzen 5 7530U) определение говорящих занимает ~6% длины записи при сплошной речи, **час ≈ 3,5 минуты** сверх распознавания; паузы и тишина ускоряют (§9).

### Этапы и прогресс

Бэкенд шлёт событие `file-transcription-progress` с полями `stage`, `part`, `total_parts` и `fraction` (0…1). Доли общей шкалы считаются в начале каждой задачи по тому, сколько секунд работы на минуту записи занимает каждый этап (`StageWeights` в `file_transcription/mod.rs`, почему так — §5.23):

| Этап | Секунд на минуту записи | Откуда число |
| --- | --- | --- |
| Извлечение звука | 0,15 | замер: 2–5 с на файл |
| Определение говорящих (если включено) | 4,5 | замер: 3,9–4,8 |
| Распознавание на этом компьютере | 3 для быстрых моделей (скорость в каталоге ≥ 0,8: GigaAM, Parakeet); медленнее — плюс 52 за каждую единицу скорости ниже 0,8 | замер: GigaAM 2,4–3,6, Qwen3-ASR 1.7B (0,38) 24–27 |
| Распознавание у модели без оценки скорости | 10 | оценка |
| Облачное распознавание | 3 | оценка |
| Нейросеть на этом компьютере (встроенная или свой сервер на localhost) | 25 | замер: Gemma 4 E4B QAT 22–27 |
| Облачная нейросеть | 3 | оценка |

Доля этапа — его число, делённое на сумму чисел этапов, которые в этой задаче есть. Пример: GigaAM + говорящие + встроенная нейросеть — извлечение 0,5%, говорящие 14%, распознавание 9%, нейросеть 77%. Запись файла — последний шаг (99%).

Внутри этапа прогресс считается по отрезкам (локально) или по кускам текста (LLM). Короткая запись, которая уходит нейросети одним куском (до ~3000 знаков, это около 4 минут речи), стоит на одном проценте, пока кусок не вернётся.

Если задан скрипт событий (§3.2), тот же прогресс из той же точки (`Progress::emit`) уходит и в него, но не чаще заданного интервала (по умолчанию 10 с).

## 5. Ключевые решения и почему они такие

### 5.1. ffmpeg, а не встроенный декодер

Чистый Rust-декодер (`symphonia`) не умеет Opus, а именно Opus обычно внутри webm (запись из браузера) и mkv (OBS). ffmpeg читает всё. Встраивать ffmpeg в установщик не стали: сборка весит ~227 МБ, а установщик Handy Plus — ~21 МБ. Поэтому ffmpeg ищется в системе (§2).

### 5.2. Промежуточный PCM-файл

Звук сначала целиком извлекается в сырой PCM (16 кГц, моно, 16 бит; ~115 МБ на час) во временную папку `%TEMP%\handy-file-…`. Причины:

- webm из браузера часто без длительности и без индекса перемотки, и резать исходник по времени ненадёжно;
- из PCM любой диапазон читается мгновенно и точно до сэмпла;
- в памяти одновременно только текущая часть (≤ 29 мин ≈ 110 МБ).

Временная папка удаляется при любом завершении: успех, ошибка или отмена.

### 5.3. Нарезка на равные части с разрезом в паузе

Число частей `N = ⌈длительность / (максимум − 20 с)⌉`, границы ставятся на `длительность·i/N`, затем каждая сдвигается в самый тихий 50-мс кадр в пределах ±10 с. Запас в 20 с гарантирует, что после сдвига ни одна часть не превысит максимум. Пример: 62 мин при максимуме 29 мин → 3 части по ~20:40, а не 29 + 29 + 4.

### 5.4. Отрезки 12–25 с по паузам для локальных моделей

Модели Handy рассчитаны на реплики диктовки, а ONNX-движки (GigaAM, Moonshine, SenseVoice…) не предназначены для получаса звука за раз. Поэтому каждая часть режется на отрезки **12–25 с**, разрез делается в самом тихом месте окна. Отрезки тише −50 dBFS пропускаются: подача тишины в Whisper — классическая причина «галлюцинаций» вроде «Продолжение следует…».

**Точка на стыке.** Если отрезок закончился без знака препинания, а следующий начинается с заглавной буквы, ставится точка: разрез сделан в паузе, значит это конец предложения. Для Whisper правило **не применяется**: он пишет с заглавной начало _любого_ отрезка, и правило давало ложные точки («Если нет. Переходим…»). Семейство модели определяется по загруженному движку (`loaded_model_is_whisper()`).

**Почему не длинные отрезки для Whisper.** Эту гипотезу проверили на 6-минутной записи Whisper Large v3:

| Вариант                                   | Знаков конца предложения | Ложных точек |
| ----------------------------------------- | ------------------------ | ------------ |
| Отрезки 12–25 с                           | 33                       | 0            |
| Отрезки 12–25 с + правило заглавной буквы | 42                       | 4            |
| Отрезки 60–120 с                          | 25                       | 0            |

Оставлен первый вариант. Для сравнения: GigaAM v3 на той же записи — 0 пропущенных концов предложений. Если у Whisper пунктуации не хватает, включите «Обработать через LLM»: нейросеть расставит её по смыслу.

Длинный текст отрезка (у облачных моделей — вся часть) при записи в документ делится по предложениям на абзацы примерно по 700 символов. Тайм-код получает первый абзац отрезка.

### 5.5. Модель не выгружается посреди задачи

В Handy есть настройка «выгружать модель сразу / через N минут». Иначе модель перезагружалась бы после каждого 20-секундного отрезка или между частями, пока работает LLM. В `TranscriptionManager` добавлен флаг `batch_hold`: пока он поднят, не срабатывают ни немедленная выгрузка, ни таймер простоя. После задачи флаг снимается, и обычные правила работают дальше.

### 5.6. Облако: mp3 48 кбит/с и лимит gpt-4o

Сервисы OpenAI и Groq принимают до 25 МБ за запрос. 29 мин несжатого звука — ~55 МБ, а в mp3 48 кбит/с моно — ~10 МБ, для речи без потери качества. Модели `gpt-4o-transcribe` и `gpt-4o-mini-transcribe` отвергают записи длиннее ~1400 с, поэтому для них максимум части автоматически снижается до 23 мин. Для моделей с «whisper» в названии запрашивается `verbose_json`: так получаются настоящие тайм-коды сегментов.

### 5.7. LLM кусками по ~6000 символов

Если отдать нейросети сразу полчаса текста (30–40 тыс. символов), она склонна сокращать и пересказывать, а длинный ответ может обрезаться. Поэтому текст части делится на куски по абзацам (≈6000 символов), а стандартный промпт прямо запрещает сокращать. Если кусок не удалось обработать (ошибка API, пустой ответ), в документ идёт исходный текст этого куска, а в результате появляется предупреждение. Задача целиком не падает.

Раньше (до §5.18) ответ нейросети собирался по меткам спикеров, и реплики, разделённые одинарным переводом строки, слипались в один абзац. Теперь абзацы собираются по номерам строк, и этой проблемы нет.

### 5.8. Новые версии: уведомление, а не автообновление

Встроенный апдейтер Handy скачивает официальные релизы Handy: он поставил бы Handy поверх Tishe. До публичного выпуска проверка была выключена намертво. С выпуска 2026-10-15 Tishe сама спрашивает свои выпуски:

- Номер версии Tishe совпадает с версией Handy (0.9.8), поэтому выпуски различаются датой. Она записана в `src/lib/release.ts` (`TISHE_RELEASE = "2026.10.17"`, при втором выпуске за день — `2026.10.17.2`), а тег выпуска на GitHub — `v` и эта дата. Предрелиз получает тег с хвостом `-pre` (первый — `v2026.10.17-pre`, 2026-10-17) и отметку pre-release на GitHub: такой тег не похож на дату, и проверка его пропускает дважды — по тегу и по отметке. Так предрелиз можно раздать тестировщикам, не предлагая его остальным.
- При запуске и по «Проверить сейчас» или пункту трея интерфейс один раз запрашивает список выпусков `https://api.github.com/repos/PereverzevVV/tishe/releases` и берёт самый новый тег-дату среди опубликованных (черновики, пре-релизы и теги не в виде даты, например `build-deps`, пропускаются, даже если `build-deps` забыли отметить пре-релизом). Если на GitHub новее, в строке состояния появляется «Вышла версия 2026.10.20», нажатие открывает страницу выпуска. Ручная проверка коротко пишет «Это последняя версия» или «Не удалось проверить обновления».
- Отправляется только сам запрос; ни записи, ни тексты, ни настройки не уходят. Переключатель «Приложение → Обновления → Проверять обновления» выключает проверку. `update_checks_forced_disabled()` снова такой же, как у Handy: проверку запрещает только переменная `HANDY_DISABLE_UPDATER`.
- Сам апдейтер Handy в окне больше не стоит (`StatusBar` показывает `ReleaseNotice` вместо `UpdateChecker`), а его адрес в `tauri.conf.json` на всякий случай указывает на выпуски Tishe.

**Почему не встроенное автообновление Tauri.** Оно работает и без платного сертификата, но ему нужен свой ключ подписи minisign: закрытый ключ хранится у владельца, каждая сборка подписывается, а в выпуск кладётся `latest.json`. И оно сравнивает номера версий, а наш номер не растёт между выпусками. Для первого выпуска хватает уведомления со ссылкой; автообновление — следующим шагом, вместе с собственным номером версии.

### 5.9. Очередь: каждый файл — отдельная задача

Очередь живёт в интерфейсе и вызывает бэкенд **по одному файлу**, ровно так же, как раньше вызывался одиночный файл. Между файлами не переносится ничего:

- каждый вызов `transcribe_media_file` создаёт свою временную папку, свои части и свой документ;
- распознавание: Whisper получает только словарь из настроек (не текст прошлых отрезков, `condition_on_prev_tokens` выключен), ONNX-модели не хранят состояния;
- LLM: каждый кусок — отдельный запрос без истории диалога; у локальной нейросети один слот и без кэша между запросами.

Единственное, что сохраняется между файлами, — загруженные в память модели, чтобы не грузить их заново. Для этого интерфейс на время очереди поднимает «удержание» (`set_file_queue_hold`): ни модель распознавания, ни локальная нейросеть не выгружаются между файлами, даже при настройке «выгружать сразу».

### 5.10. Локальная нейросеть — отдельный скрытый процесс

Встроить llama.cpp прямо в Handy нельзя без конфликта: transcribe-cpp (движок Whisper) кладёт рядом с программой свои `ggml*.dll`, а у llama.cpp библиотеки с теми же именами, но другой версии. Поэтому в установщик положен готовый `llama-server.exe` из официального релиза llama.cpp (CPU-сборка, `b11415`) со своими DLL в отдельной папке `llama\`.

- Handy запускает его сам, без окна, на `127.0.0.1` и случайном свободном порту, только когда нужна обработка, и разговаривает с ним тем же OpenAI-совместимым клиентом, что и с облачными поставщиками. Снаружи компьютера сервер недоступен.
- Параметры: контекст 8192 токена, один слот, ответ не длиннее 3072 токенов, температура 0,2 вместо стандартных 0,8. Для редактуры нужна низкая температура: при 0,8 Gemma в замере исказила два названия компаний и выбросила слова. Но и при 0,2 повторный прогон выбросил два слова, так что выигрыш по качеству не доказан (§5.15). Температура задаётся при запуске сервера, поэтому действует и на пост-обработку диктовки — это тоже редактура.
- `--cache-ram 0` (с 2026-10-07): сервер не хранит в оперативной памяти копии прошлых запросов (по умолчанию до 8 ГБ). Они ускоряют только повтор того же запроса, а при обработке файла каждый кусок новый. Общая инструкция в начале запроса по-прежнему переиспользуется из слота. На текст флаг не влияет. Сколько памяти это экономит на практике, не замерялось. Стенд работает с этим флагом с 2026-10-06 (§5.19).
- `--threads-batch` = число логических потоков процессора (с 2026-10-07; на Ryzen 5 7530U — 12). Ответ по-прежнему пишется на стандартном числе потоков — по одному на ядро. Чтение запроса (21–33% времени нейросети) — чистая арифметика, и второй поток каждого ядра ему помогает. Замер на Ryzen 5 7530U, Gemma 4 E4B QAT, 2 русских куска × 4 прогона, стандарт и новый флаг попеременно: чтение запроса 35,4 → 32,0 с и 39,2 → 34,1 с, весь кусок 104,6 → 96,8 с и 113,7 → 108,3 с (−5…−8%). Каждый прогон с флагом быстрее каждого прогона без него. Исправления и порчи в пределах разброса повторов. На процессорах без двух потоков на ядро флаг ничего не меняет. Первый замер не в счёт: в это время на машине шла сборка.

**Распознавание следующей части во время редактуры предыдущей — проверено, отклонено (2026-10-07).** Замер на Ryzen 5 7530U. Qwen3-ASR 1.7B (работает на встроенной видеокарте, Vulkan0) распознавал 20-секундный кусок по кругу (`handy.exe -f … --repeat`), а в это время стенд гонял Gemma 4 E4B QAT на двух русских кусках × 2 повтора.

| | По отдельности | Одновременно |
| --- | --- | --- |
| Распознавание 20 с звука | 6,4 с | 17–31 с |
| Нейросеть, 4 куска | 410 с | 464 с |
| Та же работа целиком | 526 с | ~464 с (−12%) |

Обе задачи упираются в общую память, поэтому мешают друг другу. В программе распознавание шло бы только во время редактуры предыдущей части, и под нагрузкой оно за ней не успевает. Оценка для часовой записи из 3 частей (Qwen3-ASR 1.7B + Gemma E4B): ~3 мин из ~46, около 6%. Для GigaAM меньше минуты: оно распознаёт час звука за ~3 мин (0,9 с на 20 с). Цена — переделка конвейера (две задачи одновременно, отмена, прогресс) и обе модели в памяти сразу. Сейчас нейросеть специально запускается только после распознавания. Не делаем.
- Процесс помещён в объект задания Windows (job object) с флагом «убить при закрытии»: если Handy упадёт или его снимут через диспетчер задач, нейросеть завершится вместе с ним.
- Падение нейросети не роняет Handy: следующий запрос просто запустит её заново.
- Журнал сервера: `%LOCALAPPDATA%\io.github.pereverzevvv.tishe\logs\llama-server.log`. Он дописывается при каждом запуске (каждый запуск начинается строкой `===== дата время · model … =====`), а не затирается: так видны скорости всех прошлых задач. После 5 МБ текущий журнал переименовывается в `llama-server.old.log` и начинается новый.

**Защита от зацикливания.** Маленькие модели иногда начинают повторять текст по кругу. На замере однообразный кусок в 3000 знаков превратился в 20 000 знаков за 7,5 мин, пока не кончился контекст. Поэтому ответ ограничен 3072 токенами, а если он в 1,5 раза длиннее входа (плюс запас), в документ идёт исходный текст куска и добавляется предупреждение. Для локальной нейросети куски уменьшены до ~3000 знаков: маленькая модель на коротком тексте точнее, а прогресс идёт чаще.

### 5.11. Остальное

- Надписи в документе («Часть», «Длительность»…) передаёт интерфейс, поэтому документ на языке приложения.
- Одновременно выполняется только одна задача, повторный запуск получает понятную ошибку.
- ffmpeg запускается без всплывающих консольных окон (`CREATE_NO_WINDOW`) и гарантированно завершается при отмене.

### 5.12. Скрипт событий: JSON в stdin, а не встроенные интеграции

Нужно было показывать прогресс в Coucou, но решение не должно знать ни о Coucou, ни о путях на конкретном компьютере: Tishe планируется выложить в открытый доступ. Поэтому Tishe умеет ровно одно — запустить программу, которую выбрал пользователь, и передать ей событие. Всё остальное делают скрипты-переходники в `examples/event-scripts/`. Это тот же приём, что у оригинального Handy в «Способ вставки → Внешний скрипт».

- **Одна строка JSON в stdin**, а не аргументы командной строки: кириллица и кавычки в путях не ломаются, а новые поля добавляются без изменения вызова. Поле `version` меняется только при несовместимых изменениях.
- **Готовая строка `message`** на языке интерфейса: простому скрипту не нужно ничего форматировать. Шаблоны передаёт интерфейс (как и надписи документа), бэкенд подставляет часть, процент и минуты.
- **Безотказность.** Скрипт запускается в отдельном потоке, задание его никогда не ждёт. Скрипт, работающий дольше 10 с, принудительно завершается. Ошибки пишутся только в журнал. События одного файла приходят строго по порядку; если скрипт не успевает, промежуточные `progress` схлопываются до последнего, а события начала и конца не теряются.
- **Интервал прогресса настраивается, по умолчанию 10 с**: прогресс у локальной модели обновляется на каждом 12–25-секундном отрезке, а один запуск `.ps1` через PowerShell занимает ~0,3–0,35 с (замер в §9). Для получасовой задачи 10 с достаточно, чтобы видеть движение, и не плодит сотни запусков. Смена этапа или части отправляется сразу. Значение ограничено 1–600 с и хранится вместе с остальными настройками вкладки.
- **Оставшееся время** — простая экстраполяция «прошло × (1 − доля) / доля». Это оценка: распознавание и LLM идут с разной скоростью. Поэтому она появляется только после 15% и 30 с работы.
- **Настройка живёт на «Расшифровке»** («Дополнительно → Интеграции», `file_transcription.json`), а не в общих настройках Handy: события пока есть только у расшифровки файлов, и так не меняется `settings.rs` оригинального Handy, что упрощает вливание его обновлений.
- **Отклонено:** свой клиент именованного канала Coucou внутри Handy (привязка к одной программе); HTTP-вебхук (нужен сервер на стороне получателя, а локальным программам проще stdin); файл состояния, который опрашивают (задержка и лишняя запись на диск).

### 5.13. Разделение по говорящим

**Отдельный слой по целому файлу, а не по частям.** Распознавание речи не умеет различать людей, нужен отдельный шаг. Он запускается сразу после извлечения звука, по всему `audio.pcm`, до нарезки на части. Поэтому один и тот же человек остаётся «Спикером 1» на всей записи, и не нужно «сшивать» спикеров между частями. Файл читается окнами, память не растёт с длиной записи.

**Сначала говорящие, потом текст.** Реплики «кто и когда» становятся границами для локальной модели: отрезки 12–25 с режутся ещё и по смене спикера, поэтому у каждого отрезка ровно один спикер. Отдельное «выравнивание» текста по словам не нужно, и точность распознавания не страдает.

- Тишина между репликами делится в самом тихом месте.
- Где двое говорят одновременно, побеждает более длинная реплика.
- Реплики короче 1 с («да», «угу») приклеиваются к соседней: такой обрывок модель распознаёт плохо.

Облачным моделям с тайм-кодами спикер ставится по наибольшему перекрытию сегмента с репликами.

**Как это работает** (тот же рецепт, что у pyannote и sherpa-onnx):

1. Окно 10 с идёт по записи с шагом 2,5 с. Модель сегментации pyannote 3.0 для каждого кадра (~17 мс) говорит, кто из ≤3 «местных» голосов звучит.
2. Для каждого голоса с ≥1 с речи без наложений модель голосов считает отпечаток (вектор) по середине этой речи, не длиннее 5 с. Признаки звука — fbank 80 полос из transcribe-rs, с вычитанием среднего.
3. Отпечатки всего файла группируются по косинусной близости. Порог 0,6, группы меньше 6% отпечатков поглощаются ближайшей.
4. Кадры раскрашиваются по группам. Разрывы меньше 0,5 с закрываются, реплики короче 0,3 с отбрасываются. Спикеры нумеруются по первому появлению.

**Почему свой код на ONNX Runtime, а не sherpa-onnx.** sherpa-onnx приносит свою копию ONNX Runtime, а Handy уже связан с ONNX Runtime через transcribe-rs (`ort =2.0.0-rc.12`, базовая сборка без AVX2, см. комментарий в `Cargo.toml`). Две копии в одном процессе конфликтуют. Поэтому взяты те же модели, что у sherpa-onnx, и около 700 строк Rust поверх уже подключённого `ort`.

Проверка: на эталонной записи sherpa-onnx `0-four-speakers-zh.wav` (4 человека, 57 с) границы реплик совпали с опубликованным результатом sherpa-onnx с точностью до 0,03 с.

**Подбор параметров.** Замер шёл на этом компьютере (Ryzen 5 7530U) на искусственных диалогах из 2–4 разных лекторов (куски по 2–20 с из учебных лекций) с известной разметкой.

| Что сравнивали                                                  | Результат                                                                                                                                               |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Шаг окна 1 с (как в pyannote) против 2,5 с                      | одинаковая точность, 2,5 с в 2,7 раза быстрее → 2,5 с                                                                                                   |
| WeSpeaker ResNet34 против 3D-Speaker ERes2Net                   | при известном числе людей одинаково (~9% ошибок спикера); в автоматическом режиме WeSpeaker даёт меньше ложных «спикеров» → WeSpeaker по умолчанию      |
| Отпечаток по всей речи окна (до 10 с) против середины 5 с / 3 с | точность та же (у трёх лекторов даже лучше: 1,5% ошибок вместо 6,8%), отпечатки на 30% быстрее → 5 с. На записи 48 мин: 230 с → 167 с                   |
| Порог 0,4 / 0,5 / 0,6                                           | 0,6 даёт меньше ложных спикеров при той же точности                                                                                                     |
| Без поглощения мелких групп / 3% / 6%                           | без поглощения находилось 3 спикера вместо 2 и 5 вместо 4 (лишние — обрывки по 1–11 с); с 6% — 2 из 2 и 4 из 4, у трёх лекторов один лишний обрывок 4 с |

**Почему число людей не передаётся в кластеризацию напрямую.** Если просто остановить слияние групп на N, то оторванный обрывок (кашель, смена микрофона) далёк от всех и доживает до конца как «спикер», а два настоящих голоса сливаются. Так и случилось на проверке: при «2 человека» почти весь текст ушёл «Спикеру 1». Поэтому сначала группы находятся по порогу (с поглощением мелких):

- если групп больше N, целые группы сливаются по близости;
- если меньше, порог ступенями ужесточается.

Если людей явно меньше, чем указано, лишний спикер не выдумывается.

**Отклонено:**

- **Диаризация по частям** — пришлось бы узнавать людей между частями.
- **Облачные сервисы «всё-в-одном»** (OpenAI `gpt-4o-transcribe-diarize`, Deepgram, AssemblyAI) — запланированы следующим этапом.
- **Модель 3D-Speaker CAM++** — не проверялась.

### 5.14. Замечания обработки и журналы

Разбор трёх прогонов часового интервью (2026-10-06) упёрся в то, что данных о прошлых задачах не осталось:

- предупреждения («кусок не обработан») показывались только в окне;
- `llama-server.log` перезаписывался при каждом запуске;
- `handy.log` хранил 500 КБ, и распознавание одного часа записи (сотни строк на отрезок) вытесняло всё раньше.

Поэтому:

- время каждого этапа (по частям тоже) пишется одной строкой `File transcription times: …` в `handy.log`, а каждое предупреждение — строкой `File transcription warning: …`;
- то же время и все предупреждения попадают в конец документа, раздел «Замечания обработки». Документ сам показывает, как он сделан, и по нему можно сравнивать модели;
- журналы стали больше и не затираются (§5.10, §6).

Отклонено: отдельный файл-отчёт рядом с документом — его легко потерять при пересылке документа.

### 5.15. Редактура «списком правок» — проверено, пока отклонено

Идея: нейросеть возвращает не весь текст заново, а только список правок вида `[2] «Корпорайт Файнанс» → «Corporate Finance»`. Программа применяет правку, только если цитата найдена дословно. Ответ короче — должно быть быстрее, и каждую правку можно проверить.

Замер 2026-10-06 на этом компьютере (Ryzen 5 7530U). Кусок 2 730 знаков расшифровки GigaAM, Gemma 4 E4B. Эталон — 21 заранее размеченная ошибка: 14 в словах и терминах, 7 в пунктуации. Эталон составлен по двум независимым расшифровкам того же звука (GigaAM и Qwen3-ASR), запись не переслушивалась.

| Способ | Время | Исправлено | Пропущено | Исправлено неверно | Новые ошибки |
| ----------------------------------------- | ----- | ---------- | --------- | ------------------ | ------------ |
| Переписать весь текст, температура 0,8 (как сейчас) | 117 с | 11 | 3 | 7 | 2 |
| Переписать весь текст, температура 0,2 | ~120 с | 11 | 4 | 6 | 0 |
| Список правок: только слова | 62 с | 3 | 13 | 5 | 1 |
| Список правок: слова и пунктуация | 134 с | 7 | 8 | 6 | 3 |

Вывод:

- список правок пропускает в 2–4 раза больше ошибок, чем полная редактура;
- вариант с пунктуацией ещё и медленнее: модель выписывает десятки «правок», которые ничего не меняют;
- поэтому основной режим — полная редактура;
- температура 0,2 в первом прогоне дала ноль новых ошибок, но повтор того же запроса выбросил P&L и «морская» (см. ниже). Температуру 0,2 оставили как разумную для редактуры, но доказанного выигрыша по качеству у неё нет.

**Повторы (2026-10-06, тот же кусок, Gemma 4 E4B, температура 0,2).**

| Инструкция и вход | Исправлено | Неверно | Новые ошибки |
| ----------------- | ---------- | ------- | ------------ |
| Прежняя инструкция, с заминками — прогон 1 | 11 | 6 | 0 |
| Прежняя инструкция, с заминками — прогон 2 | 10 | 8 | 2 (удалены P&L, «морская») |
| Прежняя инструкция, без заминок | 11 | 7 | 2 (те же) |
| Переписанная подробная инструкция, без заминок | 11 | 7 | 3 (+ искажённое название сервиса) |

Вывод:

- **два прогона одной и той же инструкции различаются так же сильно, как две разные инструкции.** Один прогон на одном куске не может доказать, что инструкция лучше;
- удаление заминок перед нейросетью качество не ухудшило;
- переписанная инструкция лучше не стала. Поэтому встроенные инструкции остались прежними, слово в слово (§5.17).

Сравнивать инструкции и модели нужно на нескольких кусках, с 3+ повторами каждого («стенд», план этапа 4).

**Поправка (2026-10-06, вечер).** В шаблонах разметки этого эталона нашлись 5 ошибок (§9.3). Числа в таблицах выше посчитаны старыми шаблонами: «исправлено неверно» завышено примерно на 3, «исправлено» занижено на 1. Сравнение строк между собой остаётся честным, шаблоны у всех одни и те же. Удаление «морская» в «морская, морские перевозки» — это убранная оговорка, а не новая ошибка.

По публикациям то же самое: нейросети общего назначения без дообучения часто ухудшают точность расшифровки и выдумывают 3–12% слов. Надёжнее использовать их как проверяющих, а не как «переписчиков» (arXiv 2405.15216, 2505.24347).

### 5.16. Ускоритель (speculative decoding) для локальной нейросети

**Зачем.** При полной редактуре нейросеть переписывает весь текст заново, поэтому почти всё время уходит на генерацию: у Gemma на этом компьютере ~9–10 токенов/с. Текст при редактуре в основном совпадает с исходным. В таком случае угадывать слова вперёд выгоднее всего.

**Как работает.** Маленькая модель-помощник (или встроенная в основную «голова» MTP) предлагает несколько следующих токенов. Основная модель проверяет их одним проходом и принимает совпавшие. Каждый токен проверяет основная модель, поэтому текст тот же, что и без ускорителя. Меняется только скорость, если угадывание окупается.

**Что выбрано.** Встроенный llama-server (`b11415`) уже умеет оба нужных режима, обновлять его не пришлось:

- `draft-mtp`. Для Qwen3.5 голова MTP лежит прямо в файле модели (сборки unsloth «-MTP»). Для Gemma 4 это отдельный файл-«ассистент» от Google (~100 МБ), передаётся через `--model-draft`.
- `draft-dspark`. Отдельный «черновик» на ~0,2–0,7 ГБ от Liquid AI и OpenBMB для их моделей.

Сколько слов угадывать вперёд (`--spec-draft-n-max`): Qwen — 3, Gemma — 2, DSpark — 6. Это стартовые значения. Карточки моделей советуют 2–10, но эти цифры измерены на видеокартах, а на процессоре каждое отвергнутое угадывание дороже. Значения подбираются замером на эталоне.

**Почему ускоритель Gemma от amaranus, а не от AtomicChat.** Основная модель — сборка Google QAT (обучена переживать сжатие до 4 бит, теряет меньше качества, чем обычный Q4_0). Google выпустил ассистента именно под QAT-веса (`google/gemma-4-E4B-it-qat-q4_0-unquantized-assistant`). Его GGUF-версию выложил amaranus. Ассистент AtomicChat сделан для обычных весов и угадывал бы хуже. На качество текста это не влияет, только на скорость.

**Почему отдельные папки.** unsloth называет файлы MTP-сборок так же, как обычные (`Qwen3.5-2B-Q4_K_M.gguf`). В общей папке программа приняла бы обычную Qwen за скачанную MTP-версию. Поэтому у новых моделей своя папка `llm-models\<id>\`, а прежние пять остались на старом месте.

**Замер на стенде (2026-10-06, §9.3).**
- Gemma 4 E4B QAT с ассистентом быстрее обычной Gemma E4B в 1,19–1,27 раза, текст того же качества.
- Qwen3.5 4B MTP быстрее Qwen3.5 4B в 1,19–1,27 раза. Qwen3.5 2B MTP почти не выигрывает: 1,02–1,10.
- Угадывания принимаются на 89–99%. Но на процессоре проверка угаданного стоит дорого, поэтому выигрыш ~1,2–1,3×, а не 1,5–2× из карточек.
- Чтение запроса (21–33% времени нейросети) ускоритель не трогает.
- **MTP-сборки Qwen — не те же веса.** Это более новая сборка unsloth: другой шаблон чата, часть весов сжата иначе (ssm_alpha/beta в F32 вместо Q8_0, attn_qkv Q4_K/Q6_K вместо Q5_K). На русском эталоне Qwen 4B MTP исправила 7 ошибок из 21, старый файл — 1–3.
- DSpark у LFM2.5 принимает 47–60% угаданного, у MiniCPM5 — 66–95%.

**Что уже было отклонено.** Ускоритель ngram (угадывание по повторам в самом тексте) на этом компьютере не дал ничего: принималось 38% угаданного, скорость не выросла (замер 2026-10-06 на часовом интервью).

**Что не взяли в каталог** (обзор Hugging Face 2026-10-06):

- Qwen3.8 и Qwen3.6 — нет лёгких версий, только от 27B.
- Ministral 3 3B и Phi — нет русского.
- T-lite 2.1 и YandexGPT-5-Lite — 8B без «экспертов», на процессоре медленные, как Qwen 9B.
- GFusion-10B-A1.8B (Сбер) — диффузионная модель, llama.cpp её, по всей видимости, не поддерживает.
- DiarizationLM-Gemma-4-E4B (Google) — только правит границы реплик между говорящими и обучена на английском, полную редактуру не делает. Может пригодиться позже как отдельный шаг для английских записей.

### 5.17. Язык текста: инструкция, защита от перевода, заминки

**Что случилось.** Английский подкаст (8 мин, Parakeet + Gemma, 2026-10-06) вышел наполовину на русском. Gemma перевела первый кусок, потому что встроенная инструкция бралась на языке интерфейса, то есть на русском.

**Что сделано.**

1. **Язык определяется по самому тексту** каждой части (whatlang, уже есть в Handy), а не по настройке распознавания. Настройка часто стоит на «ru», когда английская модель расшифровывает английский файл. Если текста меньше 40 букв, берётся настройка. Найденный язык пишется в «Замечаниях обработки».
2. **Встроенная инструкция берётся на языке текста.**
   - Для русского — прежняя русская, для английского — прежняя английская, обе слово в слово (тест это проверяет).
   - Для остальных языков — английская с добавкой «отвечай на языке текста, не переводи».
   - Если пользователь вписал свою инструкцию, она действует для всех языков. Пустое поле означает встроенную.
   - Переписывать формулировки не стали: подробная инструкция на эталоне лучше не стала (§5.15).
3. **Защита от перевода в коде.** Если доля кириллицы в ответе отличается от доли во входе больше чем на 40 процентных пунктов, кусок остаётся исходным, а в «Замечаниях» появляется предупреждение. Метки «Спикер» в подсчёт не входят.
4. **Заминки** (переключатель «Убирать заминки», включён по умолчанию):
   - русский: «э», «э-э…», «а-а…», «аа», «а-э», «м-м», «мм», «хм…», «гм», «эм»;
   - русский, добавлено 2026-10-07 по расшифровке GigaAM эталонного интервью:
     - растянутое «и» («и-и-и», «И-и», «и-ии»): если за ним продолжается предложение, остаётся слово «и» («свой, и-и-и понять» → «свой, и понять»); перед заглавной буквой или с точкой на нём — удаляется. Без дефиса не трогается: «ИИ» — искусственный интеллект;
     - обрывки «-а,» и «-,» («В том числе, -, также» → «В том числе, также»). Одиночный «-» без запятой — это тире, он остаётся;
     - заминка, приклеенная к слову: «чтоэээ» → «что», «заниматьсямм» → «заниматься». «мм» отрезается, только если слово со строчной буквы и перед «мм» не «а», «у», «е»: «грамм», «программ», «сумм», «дилемм», «Гримм» не трогаются;
     - одиночное «м,» с запятой, но не после числа («5 м,» — метры);
   - английский: uh, um, uhm, erm, er, hm, hmm, mmm;
   - никогда не трогаются: одиночное «а», «ах», «ну», «вот», like, you know, «mm-hmm» (оно значит «да»), «ah»/«oh»;
   - не сделано: одиночное «а» перед заглавной («а Давай»). Правило задело бы «а Москва» и другие названия;
   - вокруг удалённого: если заминка начинала предложение, следующее слово получает заглавную букву; точка с заминки переходит на предыдущее слово, когда следующее слово с заглавной;
   - для других языков ничего не удаляется;
   - чистка делается правилом до нейросети, поэтому нейросети меньше текста. Исходная расшифровка в конце документа остаётся дословной.
5. **Склеенная пунктуация.** Пробел ставится после запятой между двумя буквами («смысле,в» → «смысле, в»; «3,5» не трогается) и после точки, «!» или «?» между двумя строчными русскими буквами («хорошо.а» → «хорошо. а»). Латиница не трогается, чтобы не ломать «site.com» и «e.g.».

**Проверка на живом куске.** Тот же английский кусок (2 941 знак), с английской инструкцией: ответ полностью на английском, ни одной русской буквы вне меток (105 с).

**Отклонено:**

- Подробные новые инструкции для ru/en: на эталоне не лучше прежних (§5.15).
- Типографика правилом («ёлочки», неразрывные пробелы). Она меняет текст за пределами ошибок распознавания, пользы для точности нет.

### 5.18. Пронумерованные строки вместо меток спикеров

**Было:**
- нейросеть получала текст с метками «Спикер N:» и должна была их сохранить;
- одна лишняя или потерянная метка — и откатывался весь кусок в 3000 знаков;
- на часовом интервью Qwen3.5 2B так потеряла большую часть работы;
- тайм-коды после нейросети восстанавливались по порядку меток, а без говорящих их не было вовсе.

**Стало:**
- каждый абзац уходит нейросети строкой `[12] текст`, без меток и тайм-кодов (правило — `prompts/line_rule.txt`);
- ответ разбирается по номерам, спикер и время каждой строки берутся из наших данных. Потерять или выдумать их нейросеть не может;
- тайм-коды есть у каждого абзаца обработанного текста, и с разделением по говорящим, и без него.

**Откат по одной строке.** Строка остаётся исходной, если:
- в ответе её номера нет, номер повторился или строка пустая;
- она стала в 1,5 раза длиннее (плюс 100 знаков);
- она перешла на другой алфавит;
- **она потеряла ≥15% слов и не меньше 4 слов** («too short», с 2026-10-06). На стенде у рабочих моделей строка не теряла больше 5% слов, а модели, выбрасывавшие предложения, теряли 27–90% (§9.3). Словом считается кусок между пробелами, в котором есть буква или цифра;
- **она последняя в ответе, обрезанном по лимиту токенов** («cut off», с 2026-10-06). Такая строка кончается на полуслове. Признак обрезки — `finish_reason: "length"` в ответе сервера.

Отдельно ловится «склейка»: следующая строка пропала, а эта выросла хотя бы на половину её длины. Причины видны в «Замечаниях» («исходный текст оставлен в 3 из 12 строк (слишком короткая)»; до 2026-10-09 по-английски: «3 of 12 lines kept their raw text (too short)») и в файле `partN_3_llm_kept.tsv`.

**Возврат пропавших чисел (с 2026-10-07).** Если из строки пропала цифра, которая была во входе, исходным становится только тот отрезок, где модель её потеряла. Остальные правки строки остаются: «на там 3—5 лет вперёд через юнит экономику» → «на три-пять лет вперёд через юнит-экономику» → «на там 3—5 лет вперёд через юнит-экономику». Отрезок находится сравнением слов входа и ответа (наибольшая общая подпоследовательность, без учёта регистра и пунктуации). Числа, которые просто переехали или добавились («двадцать второй год» → «2022 год»), не трогаются. Такие строки считаются в «Замечаниях» («…исходные числа возвращены (строк: N)»; до 2026-10-09 «numbers put back in N lines») и в `partN_3_llm_kept.tsv` («number put back»).

**Другие кандидаты в «сторожа правок» проверены и отклонены** (2026-10-07). Правила применялись к сохранённым ответам 114 прогонов стенда (§9.3, §9.4) и к одной папке `.debug` из программы.

| Правило | Что поймало бы | Что испортило бы | Решение |
| --- | --- | --- | --- |
| Пропала цифра | «3—5» → «три-пять» (10 раз у Gemma E4B), ни одного неверного отката | — | **принято** |
| Новое латинское слово, которого не было во входе | «Turbinia» из «в турнике Апания», «бойweise» | верные WACC, DCF, CAPEX, SaaS, ad hoc, precedent transactions; у Gemma E4B QAT исправлено 12,8 → 9,9 из 46 | отклонено |
| То же, но только если во входе на этом месте не было латиницы | то же | WACC, DCF, CAPEX, ad hoc; исправлено 12,8 → 11,8 | отклонено |
| Заглавная буква у слова, которое во входе было со строчной | одно место на стенде («сеС» → «СС») | верное «алиса» → «Алису» в папке `.debug` из программы | отклонено: данных мало |
| Слово из смеси кириллицы и латиницы, которого не было во входе | «бойweise», «NОТ» | верные «DСF», где модель написала русскую «С» | как откат отклонено; см. ниже |

Почти все «смешанные» слова в ответах — верные латинские термины, в которых модель поставила похожую русскую букву: «DСF», «NОW». Поиском по документу такое «DCF» не найдётся. Кандидат на будущее — не откат, а замена похожих букв на буквы алфавита остального слова.

**Абзацы** теперь наши: ~1 минута или 700 знаков, новый абзац при смене говорящего. Раньше их расставляла нейросеть. Поэтому из встроенных инструкций убрана фраза «разбей текст на логичные абзацы»: она противоречила бы формату строк. Остальной текст инструкций прежний.

**Убрано:** проверка «число меток совпало», разбор меток в ответе, общая проверка «ответ длиннее входа» на весь кусок. Её заменила проверка каждой строки.

### 5.19. Стенд для сравнения моделей и инструкций

Скрипты на Python без пакетов. В репозиторий стенд не входит: это рабочий инструмент владельца вместе с эталонными записями, а не часть программы. Ниже — как он устроен, чтобы были понятны цифры в §9.

- `bench.py` прогоняет эталонные куски через модели так же, как программа: те же файлы `prompts/`, те же строки и правила отката, температура 0,2. Каждый прогон повторяется: два прогона одной инструкции различаются так же сильно, как разные инструкции (§5.15). Пишет каждый запрос и ответ, `runs.csv` и `summary.md` со средним и разбросом.
- **Метрики:**
  - скорость (знаков в секунду, токенов в секунду, доля принятых угадываний ускорителя);
  - строки с откатом;
  - доля изменённых слов;
  - по эталонному тексту — WER до и после, слов исправлено и испорчено, пунктуация (F1), заглавные;
  - по размеченным ошибкам — исправлено, осталось, неверно, новые.
- `score.py` разбирает папку промежуточных файлов настоящей расшифровки и показывает, на каком шаге (распознавание → чистка → нейросеть) слова стали верными или неверными.
- Правила стенда (`bench.py`) повторяют `numbered.rs` и `language.rs`. При их изменении стенд правится вместе с ними.
- **Доработки после первого полного прогона (2026-10-06, §9.3):**
  - перед прогоном стенд проверяет `spots.json` на исходном тексте: каждый «miss» должен в нём находиться, ни «fix», ни «damage» — нет. Так нашлась бы одна из 5 ошибок разметки, остальные видны только при разборе ответов моделей;
  - `--rescore <папка результатов>` заново оценивает сохранённые ответы по текущим `gold.txt` и `spots.json`, модели не запускаются. Нужен, когда эталон уточнён;
  - в `spots.json` появился список `liberties`: безвредные отступления от дословности («26» → «26 лет», «3—5» → «три-пять»). Они считаются отдельно от новых ошибок;
  - графа `lines_shrunk` — строки, потерявшие ≥15% слов и ≥4 слова (проверка для будущего «сторожа правок»);
  - графа `prompt_secs` — время чтения запроса;
  - сервер запускается с `--cache-ram 0`, а первый кусок каждого теста — без переиспользования прошлого запроса. Иначе повторы пропускали чтение и были на 20–30% быстрее, чем в программе;
  - если модель «размышляет» вопреки `--reasoning off`, её рассуждения сохраняются в `chunkNN_thinking.txt`;
  - правила «слишком короткая строка» и «обрезанный ответ» повторены в стенде вместе с программой (§5.18).
- **Новый кусок без папки `.debug`.** Тест-инструмент `clean_tsv_for_bench` (в `language.rs`, запускается только вручную) чистит расшифровку так же, как программа перед нейросетью: склеенная пунктуация, заминки. На вход — TSV «n, start, speaker, text», например из раздела «Исходная расшифровка» документа. На первом русском куске он совпал с прежним входом символ в символ. Команда — в README стенда.

### 5.20. Язык инструкций

Вопрос: писать ли все инструкции по-английски («отвечай на языке текста»), чтобы любой пользователь мог их прочитать и править?

**Решение:**

- **Для других языков (не ru и не en)** — английская `universal.txt` с подставленным названием языка («…recording in German… Write your answer in German, … never translate it»). Отдельную инструкцию на каждом языке не поддержать, а английскую понимают и модели, и люди.
- **Для русского и английского** оставлены проверенные прежние инструкции. Переход русских записей на английскую инструкцию — только если стенд покажет, что она не хуже (замер ниже).
- Перевод ловит код (§5.17), какой бы ни была инструкция.
- Инструкции лежат отдельными текстовыми файлами в `prompts/`, их можно прочитать и поправить без знания Rust. Своя инструкция на вкладке «Файл» заменяет встроенную для всех языков.

**Замер (§9.3):** ни одной переведённой строки в 60 прогонах 10 моделей. Русская и английская инструкции остаются раздельными: правило, которого не хватает, касается только русского (английские термины, записанные кириллицей). Английская инструкция на русском тексте (H9) проверена в §9.4 и отклонена: у маленьких моделей она резко хуже русской.

### 5.21. Параметры у каждой модели (окно ⚙)

**Хранение.** Отдельный файл `%APPDATA%\io.github.pereverzevvv.tishe\model_settings.json` (модуль `model_settings.rs`), по id модели. Общий `settings.rs` Handy не тронут, чтобы его обновления вливались без конфликтов.

**В файле только то, что пользователь поменял.** Неизменённое поле — `null`, и программа берёт стандартное значение из кода. Отсюда два свойства:
- подобранные замерами значения (температура 0,2, куски 3000, правило осторожности) нельзя «заморозить» или сбросить случайно: файла нет — всё стандартное;
- если стандарт поменяется в новой версии, он дойдёт до всех моделей, где его не трогали.

Значение, совпадающее со стандартным (или стёртое поле), сохраняется снова как «стандартное». Окно получает стандартные значения от бэкенда (`defaults`) и показывает их в полях, поэтому пустых полей нет. Бэкенд проверяет диапазоны и то, что контекст вмещает кусок и ответ; неверное значение не сохраняется, окно показывает причину.

**Перезапуск нейросети.** Сервер запоминает параметры запуска. Если они поменялись, он перезапускается перед следующим запросом, но только когда его больше никто не использует: идущая задача доработает со старыми.

**Отложено, с причинами:**
- **вариант сжатия модели распознавания** — в каталоге у каждой модели один файл, выбирать не из чего;
- **язык модели распознавания** — язык в Handy один на всю программу и используется кодом диктовки в нескольких местах `managers/transcription.rs`. Своя настройка у модели означала бы правки upstream-кода и конфликты при каждом вливании Handy. Для правил и инструкций язык и так определяется по тексту (§5.17);
- **режим «быстрая редактура» (список правок)** — отклонён замером (§5.15);
- **температура облачных поставщиков** — часть облачных моделей её не принимает, нужен повтор запроса без неё.

### 5.22. Интерфейс Tishe: разделы по сценариям и визуальная система v3

Окно Handy было оболочкой настроек: восемь разделов, рабочее место для файлов внутри «настроек», последствия спрятаны в значки ⓘ, перехода между разделами не было. Как должно быть, описывают аудит, архитектура разделов, архитектура взаимодействия и визуальная система (v3, принята владельцем 2026-10-08). Это рабочие документы владельца, в репозиторий они не входят. Пометки в коде вида «VISUAL_DESIGN_SYSTEM §12.13», «UX_INTERACTION_ARCHITECTURE S4», «VD-81», «DD-05» ссылаются на их разделы и правила.

Главные решения реализации:

- **Вид — один в один с макетом v3, содержание — по спецификациям экранов** (решение владельца 12). Макет был образцом токенов, поэтому в рецепте сделано по S1: «Где распознавать», строка «Результат · Изменить», без списка «Язык записи».
- **Свои компоненты вместо системных**: выпадающий список, меню и сегменты повторяют поведение системных с клавиатуры, но умеют описания вариантов и поиск. `react-select` остался только для ввода модели сервиса (там нужен ввод своего значения).
- **Ползунков нет** (VD-81): громкость — «Тихо / Средне / Громко», пороги и задержки — числовые поля. Отвергнуто: ползунок как новый компонент ради одной настройки.
- **Переход по ссылке с подсветкой и строкой возврата** вместо постоянной кнопки «Назад»: сайдбар плоский, «назад» нужен только после ссылки (DD-05). Цель ссылки снимается только после того, как её показали, иначе двойной запуск эффекта в StrictMode терял её.
- **Перетаскивание файлов** — одобренная владельцем возможность; без неё надпись «Перетащите запись сюда» была бы неправдой. Работает через событие Tauri, а не HTML drag-and-drop, который при включённом обработчике Tauri не срабатывает.
- **Необратимое — через диалог, обратимое — через «Вернуть»**: удаление моделей и остановка расшифровки спрашивают подтверждение с фокусом на безопасной кнопке; убрать строки из списка, удалить диктовку, инструкцию или своё слово можно сразу, с «Вернуть» в уведомлении на 6 секунд.
- **Шкалы Tailwind в пикселях**: корень стал 14 px (стандарт Windows 11), а шкала Tailwind считается в rem; без перевода в пиксели отступы и радиусы съезжали со шкалы системы (7 и 10,5 px вместо 8 и 12). Нашлось измерительным скриптом из §17 системы.
- **Второй проход того же дня** (владелец: «сделать надо всё», порядок по приоритетам) закрыл всё, что первый откладывал. Решения:
  - **Перетаскивание без синей рамки** (владелец: «некрасиво»). Над рабочей областью — фон окна на 92 % и пунктирная цель того же вида, что зона файлов на странице, с текстом о том, что будет именно с этими файлами (событие Tauri `enter` уже несёт пути). Синий больше не обозначает перетаскивание (VD-02 изменено). Проверено настоящим перетаскиванием из Проводника системным вводом мыши (§9.7).
  - **Узкое окно — полоска значков**, а не сворачиваемый сайдбар с кнопкой: срабатывает сама при рабочей области меньше 520 точек. Масштаб клавишами включён (`zoom_hotkeys_enabled`): раньше в Tauri он был выключен, и «200 %» из первого отчёта было только эмуляцией.
  - **Имя Tishe в сборке**: `productName`, заголовок окна, подсказка и меню трея. Идентификатор `com.handyplus.app` не менялся, поэтому папки данных, WebView2 и запуск одной копии те же. Установщик под новым именем — другой продукт для Windows, поэтому он сам удаляет установку «Handy Plus» (функция `RemoveHandyPlus` в `nsis/installer.nsi`, только если путь кончается на «Handy Plus»), иначе остались бы две программы в списке и два ярлыка.
  - **Результаты между запусками** — в отдельном файле `file_results.json` через `tauri-plugin-store`, только готовые документы, до 50 (CF7). Отвергнуто: таблица в `history.db` — это база диктовок со своими миграциями, а список результатов — маленький и не нужен поиску. Проверка «Документ не найден» — новая команда `paths_exist`, при открытии раздела и после неудачного «Открыть», а не постоянно.
  - **Уведомления Windows через WinRT напрямую** (`windows` crate: `ToastNotification` с обработчиком `Activated`), без новой зависимости. Отвергнуто: `tauri-plugin-notification` — на Windows не сообщает о нажатии, а нажатие должно открыть строку результата. Текст собирает окно (оно знает файлы и язык), показывает Rust только если окно скрыто, свёрнуто или не в фокусе и включена настройка. В dev-сборке нет ярлыка с идентификатором, поэтому уведомление подписано «Windows PowerShell»; в установленной — «Tishe».
  - **Трей** получил подсказку с ходом, значок «работаю» и блокировку «Модель ▸». Подсказка меняется отдельно от меню: иначе каждый процент перестраивал бы меню, а это то, от чего Handy защищался из-за пропадающего значка трея на macOS.
  - **DD-27 сделан в движке**: части файла распознаются новым методом `transcribe_verbatim`, который не применяет фильтр «Удалять слова-паразиты»; диктовка — прежним `transcribe`. Переключатель переехал из «Моделей» в «Диктовка → Дополнительно → Текст диктовки», «Убирать заминки» документа получил зеркальную подпись.
  - **Сообщения оверлея** — новое состояние «message» шириной 360 и состояние «waiting». Сообщения скрываются сами через 4–6 секунд, но только если оверлей не показали заново (счётчик показов уже был в `overlay.rs`). «Что делать» — команда `overlay_help`, окно открывается на нужной группе без строки возврата.
  - **Подтверждение выхода** — в окне, а не системным диалогом: трей показывает окно и шлёт событие `confirm-quit`. Подтверждение обновления во время расшифровки не делалось: обновления в этой сборке выключены (§5.8).
  - **«Клавиша занята»** учитывается только для системных сочетаний: только их Windows может отклонить (`HotKey already registered`). Отказ запоминается при регистрации и снимается при успешной регистрации или снятии клавиши; событие `shortcut-conflicts-changed`.
  - **Онбординг** по DD-29/DD-33: карточки языка с размерами (с 2026-10-13 их четыре: русский, английский, другой европейский, другой), «Шаг N из 3», скачивание только по кнопке. Модели выбираются по репозиторию каталога (`gigaam-v3-e2e-ctc-gguf`, `parakeet-unified-en-0.6b-gguf`, `parakeet-ultra-gguf`, `Qwen3-ASR-0.6B-gguf`; `whisper-large-v3-gguf` — только если язык Windows не знает ни одна из них), чтобы не зависеть от варианта сжатия. «Понятно» на карточке «Попробуйте» — вторичная кнопка: главная на экране одна. С 2026-10-18 карточку заменил «Быстрый старт» (§5.27).
  - **Метки «изменено» у полей в складках** (решено самостоятельно по спецификации, Progressive Disclosure, правило 3): только внутри складок, где значение не на виду. На открытой странице метки нет: значение и так видно.
  - **«Что нового» о переездах не делается** (решено самостоятельно): окно «Что нового» показывает заметки по номеру версии, а номер у сборки тот же (0.9.8) и заметки — английские заметки Handy. Где теперь какая настройка, — таблица в §3.0 и ссылки «Изменить» прямо в разделах.
  - **История по умолчанию 50** — только на свежих настройках (DD-23): у кого уже записано своё число, оно не меняется.

### 5.23. Ход расшифровки по замеренному времени, предупреждения на языке программы (2026-10-09)

**Почему поменялись доли полосы.** Раньше этапы делили полосу заданными долями: извлечение 10%, говорящие 12%, распознавание 75%, нейросеть 13%. Прогон четырёх встреч по 24–28 минут (Ryzen 5 7530U, GigaAM + говорящие + Gemma 4 E4B QAT) показал другое: нейросеть занимает 75–83% времени, говорящие 10–15%, распознавание 7–10%, извлечение меньше 1%. В итоге редактура начиналась на 87%, и 9–12 минут полоса стояла около 96% с «осталось ≈ 30–40 с». Та же доля уходила в подсказку трея и в скрипт событий.

**Как теперь.** Все этапы растут вместе с длиной записи, поэтому важно только соотношение их скоростей. Каждому этапу задано, сколько секунд работы он тратит на минуту записи (таблица в §4 «Этапы и прогресс»), и доли считаются в начале задачи из тех этапов, что в ней есть. Скорость распознавания берётся из оценки скорости модели в каталоге: на двух замеренных точках (GigaAM 0,98 и Qwen3-ASR 1.7B 0,38) прямая даёт 3 и 25 секунд на минуту, как в замере.

Проверка на одной из тех же встреч (28 мин, 15:04 всего): редактура теперь начинается на 23% (было 87%). Оценка «осталось» в начале редактуры — около 8,5 мин при настоящих 12,5; на середине редактуры — около 5,5 мин при настоящих 6. Раньше было «≈ 30 с».

**Что не учтено (отклонено как лишнее).** Скорость встроенной нейросети одна для всех моделей — 25 с на минуту, замер рекомендованной Gemma 4 E4B QAT. Gemma E2B вдвое быстрее, Qwen3.5 9B заметно медленнее; для них «осталось» ошибается в ту или другую сторону, но не в разы, как раньше. Подстраивать доли по ходу работы (по замеренной скорости предыдущих этапов) не стали: полоса тогда прыгала бы назад.

**Предупреждения и подпись нейросети.** Тексты предупреждений приходят из интерфейса вместе с надписями документа (`DocumentLabels.warnings`, шаблоны с `{part}`, `{fragment}`, `{count}`, `{kept}`, `{total}`, `{reasons}`, `{error}`), так же, как тексты для скрипта событий. Поэтому они на языке программы и в документе, и в списке файлов, и в журнале. Если интерфейс их не прислал, остаются прежние английские тексты. Файл `partN_3_llm_kept.tsv` в папке `.debug` по-прежнему пишет причины по-английски («missing», «number put back»): по нему сверяются стенд и прошлые прогоны. Встроенная нейросеть в шапке документа называется как в интерфейсе: «Gemma 4 E4B · сборка Google, на этом компьютере» (`DocumentLabels.llm_local`); облачные — как раньше, «поставщик / модель».

### 5.24. Интерфейс на всех 26 языках Handy (2026-10-13)

**Что сделано.** До этого строки Tishe были только на русском и английском, а остальные 24 языка Handy показывали их по-английски. Теперь переведено всё, что видит пользователь: разделы окна, онбординг, предупреждения и ошибки, подсказки трея, уведомления Windows, сообщения у курсора, надписи и предупреждения в готовом документе. Это 684 строки: все строки Tishe и около 90 строк Handy, которые на русском были переписаны под новые экраны (короткие подписи вместо длинных описаний Handy). Английский текст этих строк Handy приведён к русскому, иначе остальные языки переводились бы со старых формулировок Handy. Перевод сделан нейросетью (Claude) с учётом контекста каждой строки; носители языков его не вычитывали (§10).

**Строки, привязанные к русскому, в других языках переписаны по смыслу.** Владелец (2026-10-13): «предупреждения про работу на русском языке понятное дело не нужны в других языках». Поэтому:

- Описания встроенных нейросетей больше не говорят «на русских записях» и «на час русской речи»: «лучшее качество в наших тестах», «около 26 мин на час записи». Замеры по-прежнему сделаны на русских встречах (§9.3), но человеку с немецким интерфейсом эта оговорка ничего не даёт. На русском тексты не изменились. GigaChat по-прежнему подписан «для русского»: это свойство модели, и человеку с другим языком оно как раз полезно.
- Модель голосов описана как «надёжно различает голоса на реальных записях» вместо «проверена на русских записях».
- Пример кода языка у облачного распознавания — свой: «de или en», «fr или en», «ja、en».
- «Убирать заминки» в документах честно говорит, что работает только на английских и русских записях: остальные языки модуль заминок пропускает без изменений (§5.17).
- «Удалять слова-паразиты» у диктовки перечисляет то, что Handy действительно удаляет на этом языке: немецкий — «äh», «ähm», «hmm», французский — « euh », « hmm », остальные — «uh», «hmm». Прежние русское «ну, вот, типа» и английское «so, like» были неверны: Handy их не удаляет; русский текст исправлен на «хм», «ммм».
- На первом запуске карточка своего языка называет его: «Deutsch oder eine andere europäische Sprache», «日本語またはその他の言語».
- Факты о продукте оставлены как есть: встроенные инструкции нейросети есть только для русского и английского, карточка «Русский» в онбординге остаётся.

**Порядок карточек на первом запуске.** Первой идёт карточка языка Windows, затем английский, европейские, другие, а «Русский» — последней. На русской Windows порядок прежний (русский, английский, европейские, другие).

**Множественное число по правилам каждого языка.** i18next выбирает форму по правилам CLDR (`Intl.PluralRules`): польскому и украинскому нужны `_one/_few/_many/_other`, арабскому — шесть форм, японскому и китайскому — только `_other`. Если формы нет, i18next показывает английский текст. Поэтому для каждого языка записаны все его формы. Встроенная проверка Handy `check:translations` требовала у всех языков ровно английский набор ключей (`_one/_other`) — по ней польский считался бы ошибкой. Она теперь ждёт у каждого языка его формы CLDR и не считает лишними другие формы того же ключа (§6). Заодно дописаны недостающие формы у строки Handy про блокировку клавиш macOS (`secureInput.blocked*`).

**Тон и типографика** взяты из существующих переводов Handy: немецкий, шведский, датский, польский, итальянский, испанский, нидерландский — на «ты»; французский, украинский, болгарский, чешский, турецкий — на «вы»; иврит — во множественном числе (не зависит от рода). Кавычки свои у каждого языка: „…“, « … », «…», 「…」, ”…”. Названия разделов в «Назад к …» совпадают с подписями разделов в сайдбаре этого языка. В языках с другим порядком слов (японский, корейский, турецкий, хинди, непальский) фразы вокруг клавиши («Удерживайте [клавиша] и говорите») перестроены по частям.

**Порядок ключей.** Файлы языков сохраняют свой порядок ключей; новые ключи вставлены рядом с соседями по английскому файлу. Так при вливании Handy конфликты будут только в изменённых строках.

### 5.25. Подготовка к публичному выпуску (2026-10-15)

**Идентификатор `io.github.pereverzevvv.tishe`.** Tauri строит из идентификатора имена папок данных, поэтому он нужен уникальный и навсегда. Обратная запись домена, которым владеет проект, — обычное правило; своего домена у Tishe нет, а адрес на GitHub (`pereverzevvv.github.io`) есть. Отклонены: `com.tishe.app` — домен `tishe.com` чужой, а окончание `.app` Tauri не советует (путается с пакетом macOS); `app.tishe` — домен `tishe.app` не куплен.

**Перенос данных — переименованием при первом запуске** (`src-tauri/src/data_migration.rs`, вызывается первой строкой `setup`). Копирование заняло бы минуты и удвоило место под модели (гигабайты), а переименование на том же диске мгновенно. Правила (переписаны 2026-10-15 после ревью):
- Папка данных (`%APPDATA%\…`) переименовывается целиком: до `setup` новую никто не создаёт. В локальной папке (состояние окна WebView2 и журналы) Tauri к этому моменту уже открыл новый журнал, поэтому её содержимое переносится по одному, а папки сливаются.
- Файл, занятый другим процессом (задержавшийся WebView2, антивирус), пробуется ещё около двух секунд. Что так и не перенеслось, остаётся в старой папке, и следующий запуск пробует снова: признак незаконченного переноса — сама старая папка.
- При совпадении имён побеждают старые данные человека. Это важно, если первый перенос сорвался: программа успела поработать с пустыми настройками и историей, а при следующем запуске настоящие файлы иначе встали бы рядом и не использовались бы. Новый файл откладывается как `<имя>.replaced-<время>`. Если новый файл открыт (текущий журнал), старый кладётся рядом как `previous-<имя>`. Ничего не удаляется и не перезаписывается.
- Пути со старой папкой в `settings_store.json` заменяются на новую, только если что-то перенеслось.
- Перенос работает только под выпускным идентификатором: dev-сборка с `com.handyplus.dev` не заберёт данные установленной программы. Портативная установка (данные рядом с exe) не трогается. Деинсталлятор с галочкой «удалить данные» удаляет и старые папки, если перенос так и не случился.
- Только Windows: на macOS хранилище окна лежит в другой папке и не переносится (Tishe под macOS не выпускается).

**Имя `tishe.exe` через `mainBinaryName`.** Пакет Rust по-прежнему называется `handy`: переименование пакета задело бы `Cargo.toml`, `Cargo.lock` и имена библиотек Handy и усложнило бы слияния. Tauri переименовывает только итоговый exe. Установщик Tauri сам удаляет старый exe по сохранённому в реестре имени; наша вставка в `installer.nsi` перед этим закрывает запущенный `handy.exe` из папки Tishe. Поле `app` в событиях для скриптов теперь `"tishe"`.

**ffmpeg в установщике.** Сборка — BtbN FFmpeg-Builds `win64-lgpl` n8.1.3 (статическая, LGPL v3, с кодировщиком mp3 `libmp3lame`, который нужен для фрагментов в облако). Сборка gyan.dev «essentials», которую ставит winget, отклонена: она под GPL. LGPL не распространяется на Tishe, потому что ffmpeg запускается отдельной программой и не линкуется. От нас требуется положить текст лицензии и указать исходники именно этой сборки: `scripts/fetch-ffmpeg.ps1` пишет рядом `LICENSE.txt` и `SOURCE.txt` (коммит FFmpeg и коммит скриптов сборки BtbN с версиями всех библиотек). Цена — размер: `ffmpeg.exe` весит 134 МБ, в zip 57 МБ; установщик вырастет примерно на столько же (оценка, после сборки — замерить). Своя урезанная сборка «только звук» весила бы единицы мегабайт, но её надо собирать и выкладывать с исходниками самим — отложено. BtbN удаляет датированные сборки примерно через месяц, поэтому скрипт сначала берёт копию из выпуска `build-deps` в репозитории Tishe (её нужно туда положить, §8), а SHA-256 закреплён в скрипте.

**Сводный файл лицензий.** До выпуска в установщике лежала только лицензия llama.cpp; MIT Handy, крейты Rust, ONNX Runtime, ggml и пакеты интерфейса требуют прикладывать свои уведомления. `scripts/notices/gen-notices.ts` собирает `src-tauri/licenses/THIRD_PARTY_NOTICES.txt` (~1 МБ): лицензия Tishe, нативные части (transcribe.cpp, ggml, miniz, Silero VAD — прямо из исходников крейта; ONNX Runtime с его ThirdPartyNotices; ссылки на лицензии llama.cpp и ffmpeg в их папках; NSIS), 489 крейтов Rust под Windows без build- и dev-зависимостей (`cargo-about`), 192 пакета интерфейса (свой обход `node_modules` по `dependencies` вместо `license-checker`: тот рассчитан на раскладку npm, а лишняя зависимость ради одного файла не нужна) и атрибуции моделей (CC BY 4.0, NVIDIA Open Model License и др.). Файл в установщике лежит в `licenses\`, открывается из «О программе» → «Лицензии». Файл генерируется и коммитится; перегенерировать при смене зависимостей (§8).

**Некоммерческие модели не предлагаются.** Tishe под MIT, и ей могут пользоваться в работе, поэтому каталог при загрузке отбрасывает модели с лицензией `cc-by-nc-*` — сейчас это одна `nvidia/canary-1b`. Правило в `catalog/mod.rs`, а не правка `catalog.json`: файл генерирует Handy, правка мешала бы слияниям, а правило поймает и будущие такие модели. Canary 1B Flash и Canary 1B v2 под CC BY 4.0 остаются.

**README для GitHub — в `.github/`.** GitHub показывает `.github/README.md` раньше корневого, поэтому `README.md` Handy остаётся нетронутым и не конфликтует при слияниях. Русская версия основная, английская — `.github/README.en.md`. Шаблоны issues Handy отправляли людей в обсуждения Handy; теперь сообщения об ошибках идут в репозиторий Tishe (`.github/ISSUE_TEMPLATE/`).

### 5.26. Широкое окно (2026-10-15)

**Проблема.** Колонка содержимого была не шире 640 (VD-15): так строка текста не длиннее ~80 знаков. На окне, развёрнутом на экран 1920 × 1080, это оставляло по ~550 точек пустоты с каждой стороны, а кнопка «Расшифровать» в нижней панели уезжала к правому краю экрана, далеко от того, что она запускает.

**Решение (VD-86).** Ширину отдаём под больше объектов, а не под длинную строку. От 1280 точек ширины окна:
- страница расширяется до 1080 (`--t-page-wide`) и у всех разделов начинается от одного левого края — заголовок не прыгает при смене раздела;
- текстовые блоки и формы (группы настроек, предупреждения, заголовок) остаются до 640, правило VD-15 в силе;
- каждый раздел — две колонки по одному правилу «главное слева, дополнительное справа» (таблица в §3.0): слева то, ради чего открыли раздел (файлы, клавиши, список диктовок, выбор нейросети), справа шириной 400 (`--t-side-w`) — складки «Дополнительно», справочные строки и редкие настройки. Рецепт и файлы видны одновременно, без прокрутки;
- каждая группа закреплена за своей колонкой по смыслу, а не раскладывается потоком: при раскрытии складки или переходе по ссылке «Изменить» ничего не перескакивает в другую колонку, складка раскрывается вниз в своей колонке;
- более короткая колонка «прилипает» (`position: sticky`) и остаётся видна, пока прокручивается длинная, — но только если целиком помещается в окно, иначе её низ было бы не увидеть. Это решает `Page.tsx`: `ResizeObserver` следит за высотой колонок и окна и ставит класс `t-sticky`;
- левая колонка не ниже правой, но не выше видимой части окна (переменная `--t-work-fill` из `Page.tsx`): пустая зона файлов заполняет место рядом с рецептом, а при раскрытом «Дополнительно» не вытягивается на 1500 точек с надписью за краем экрана — это было в первой версии раскладки и найдено на снимках;
- в DOM порядок блоков тот же, что на обычном окне (у «Истории» и «Редактуры» правый блок идёт первым), колонки задаются явным `grid-column`. Поэтому на узком окне порядок не меняется, а Tab и экранный диктор идут в прежнем порядке;
- каталог в «Распознавании» — под колонками на всю ширину, в две колонки, список вдвое короче;
- содержимое нижней панели выровнено по странице (так и на обычном окне): кнопка «Расшифровать» стоит под правым краем содержимого.

На окне уже 1280 обёртки колонок не участвуют в раскладке (`display: contents`), и страница остаётся прежней одной колонкой 640 — ничего не меняется (проверено попиксельным сравнением снимков до и после, §9.15). Одна тонкость: правило «у последней группы нет нижнего отступа» видит обёртку как родителя, поэтому для групп внутри обёрток отступ 24 возвращён отдельным правилом, а «32 перед складкой» продолжает работать через границу обёрток. Граница считается по ширине окна (media query), а не рабочей области: контейнерный запрос на `.t-main` сделал бы её «содержащим блоком» для всего с `position: fixed` внутри, и это риск для меню и подсказок.

**Отклонено:** растянуть все страницы на ширину окна (строки по 150+ знаков, подпись далеко от своего переключателя); раскладывать группы по двум колонкам потоком, как газету (при раскрытии складки группы перескакивали бы между колонками — поэтому каждая группа закреплена за колонкой); оставить страницы настроек одной колонкой 640 (так было в первой версии: на 1920 справа от форм оставалось ~550 пустых точек, разделы выглядели «прижатыми влево»); центрировать колонку каждой страницы по своей ширине (заголовок прыгал бы на 200 точек при переходе между «Расшифровкой» и «Диктовкой»); правая колонка всегда «липкая» (если она выше окна, её низ не увидеть до конца страницы); растягивать пустую зону файлов на всю высоту правой колонки (при раскрытом «Дополнительно» надпись уезжала за край окна); расширять страницу больше 1080 на мониторах 2560 и 3440 (строки форм и так ограничены 640, а глазу пришлось бы бегать между колонками через полэкрана).

### 5.27. Первый запуск и «Быстрый старт» (2026-10-18)

**Проблема (отзыв владельца на предрелиз 2026-10-17).** Первый запуск был узкой колонкой 520 точек у верхнего края окна: развёрнутое на весь экран окно оставалось почти пустым. Когда модели не скачаны, было непонятно, куда нажимать: на «Расшифровке» и «Диктовке» стояла красная строка «Нет модели распознавания · Выбрать», которая вела в длинный каталог. После первого запуска главный экран не подсказывал, как быстро всё настроить. Включение редактуры без скачанной нейросети давало мелкую строку под переключателем, а запуск расшифровки с такой редактурой — предупреждение «ошибка нейросети» в каждом файле.

**Решение (VD-87).**
- *Рамка первого запуска* (`OnboardingShell`) стоит посередине окна при любом размере: прокручиваемый контейнер и `margin: auto` у содержимого — так середина не срезает верх на низком окне (флекс с `align-items: center` срезал бы). От 900 точек — две колонки: приветствие с тремя шагами и отметкой текущего слева, шаг справа, верхние края на одной линии. Ниже 900 приветствие сворачивается до логотипа и «Шаг N из 3», чтобы на 680 × 540 карточки языка оставались на первом экране.
- *Шаг языка*: кружок выбора на карточке (раньше выбранная отличалась только рамкой, и было неочевидно, что это выбор), одна большая кнопка на всю ширину, которая называет модель и размер. Скачивание — по кнопке, как и было (DD-33).
- *Шаг скачивания* учит, пока человек ждёт: как диктовать (с его клавишей), как расшифровать запись, где редактура. «Открыть Tishe, не дожидаясь» пускает в окно сразу: скачивание живёт в хранилище моделей, а не на экране, и продолжается; строка состояния делает модель активной, когда она скачается (`useAsrModelStatus`, это уже было).
- *«Быстрый старт»* вместо карточки «Попробуйте диктовку»: три обязательных шага (модель, диктовка, запись) и редактура отдельно, как необязательная. Шаг отмечается, когда это реально произошло (модель активна; в «Истории» есть диктовка — проверяется при показе и по событию; есть готовый файл), а не по нажатию кнопки: иначе галочка врала бы. Список хранится в `localStorage` окна (`tishe.quickStart`), а не в настройках: это не настройка, и для неё не понадобилась новая команда бэкенда. Обновившиеся с прежней версии его не видят — у них нет этого флага.
- *Карточка «Скачайте модель распознавания»* (`AsrSetupCard`) — одна и та же на «Расшифровке», «Диктовке» и «Моделях»: выбор языка записей тем же правилом, что в первом запуске (`lib/firstModel.ts` — общий для обоих), скачивание и прогресс прямо в карточке. Если модель скачалась, но ещё не стала активной, карточка до 6 секунд пишет «Готовлю модель…», а не «осталось её включить» — иначе на секунду мелькало лишнее предложение. Если модель лежит на диске, но не выбрана, — «Использовать …».
- *Нейросеть для редактуры* (`useLlmGate`): переключатель редактуры (файлы) и второй клавиши (диктовка) сначала спрашивает готовность. Готова или качается — включается сразу. Нет модели — окно с рекомендованной моделью, её размером и памятью и «Скачать и включить». Нет ключа, адреса или модели у сервера — окно называет, чего не хватает, и ведёт в «Нейросеть». «Расшифровать» с включённой редактурой ждёт готовую нейросеть, внизу — причина и «Без редактуры».
- *Что предложить для редактуры* решает одна функция `llmNextStep` (`pages/shared.tsx`) для окна, «Быстрого старта» и нижней панели: готово; качается; скачать встроенную; включить уже скачанную; настроить сервер или сервис; движка нет. Облачный сервис без ключа на Windows считается «не настроенным», а не выбором человека: так стояло у всех по умолчанию (Handy начинает с OpenAI), и предлагать вписать ключ OpenAI тому, кто ничего не выбирал, — неверный ответ для программы «без интернета». Новая установка на Windows сразу начинает со встроенной нейросети (`default_post_process_provider_id` в `settings.rs`).
- По итогам проверки кода (отдельный проход, 2026-10-18): «Расшифровать» считала моделью любую скачанную, а не включённую (каждый файл падал); после скачивания или удаления модели нейросети бэкенд сам меняет выбранную, не присылая события, — теперь `llmStore.reload` перечитывает настройки; «Открыть Tishe, не дожидаясь» в момент конца скачивания могла оставить модель невключённой — «Быстрый старт» включает модель с диска сам, один раз.
- Попутно: шаг «Разрешения» перезапускал проверку разрешений при каждой перерисовке окна — `App` передаёт новый обработчик на каждой отрисовке, а он стоял в зависимостях эффекта. Теперь обработчик читается через `ref`, проверка идёт один раз. На Windows добавлено «Продолжить без микрофона» — без него человек без микрофона застревал на первом шаге.

**Названия разделов (2026-10-18, по отзыву владельца).** «Модели» и «Нейросеть» читались как одно и то же: обе — про «модели» и «нейросети» (распознавание речи — тоже нейросеть). Разделы переименованы по тому, что они делают: «Распознавание» (речь → текст: модели распознавания, язык, свои слова) и «Редактура» (текст → исправленный текст: встроенная нейросеть, свой сервер или облако). Переключатель в рецепте «Редактура нейросетью» теперь ведёт в раздел с тем же словом. Значки — звуковая волна и волшебная палочка вместо коробки и процессора. Во всех языках тексты, которые называют раздел, берут имя через вложенный ключ `$t(sidebar.models)` / `$t(sidebar.llm)`, чтобы при следующем переименовании не искать их по всем 26 файлам. Отклонено: «ASR» (непонятно не-разработчику), «Модели речи» и «Нейросеть для текста» (снова «модели» и «нейросеть» рядом), переименовать только один раздел (пара «Распознавание» — «Нейросеть» всё равно путает: распознаёт тоже нейросеть).

**Отклонено:** «Пропустить» на шаге языка (тогда `onboarding_completed` осталось бы ложным — его ставит только выбор модели, — и первый запуск показывался бы снова; нужна была бы новая команда бэкенда, а «Открыть Tishe, не дожидаясь» решает ту же задачу без неё); показывать «Быстрый старт» всем, в том числе обновившимся (им он не нужен — модель и привычки уже есть); отмечать шаги по нажатию кнопок (галочка ставилась бы, даже если диктовка не сработала); всплывающее уведомление вместо окна при включении редактуры без нейросети (уведомление уходит само, а решение — скачать почти 3 ГБ или настроить сервер — требует внимания); запрещать запуск расшифровки без модели заранее, не давая добавить записи (человек, у которого модель качается, хочет сразу положить файлы в очередь).

Вся работа Tishe лежит в git-ветке `handy-plus` (имя ветки осталось от прежнего названия), по одному коммиту на задачу. Ветка `main` — нетронутая копия Handy, из неё вливаются обновления. Посмотреть все отличия от Handy: `git diff main handy-plus`.

### Как вливаются обновления Handy

1. `git fetch origin` — скачать новые коммиты Handy.
2. `git branch -f main origin/main` — передвинуть `main` на них (своих коммитов в `main` нет, поэтому это безопасно).
3. На ветке `handy-plus`: `git merge main`.
4. Конфликты бывают там, где наши правки соседствуют с правками Handy: `tauri.conf.json` (оставляем имя «Tishe», `mainBinaryName` и `io.github.pereverzevvv.tishe`, версию берём новую), `managers/transcription.rs`, `lib.rs`, `RecordingOverlay.tsx`, файлы переводов en/ru. Заранее увидеть их без изменения рабочих файлов: `git merge-tree --write-tree --name-only handy-plus origin/main`. Затем `cargo check`, тесты, `bun x tsc --noEmit` и проверка в собранном приложении (§9).

**Правило с 2026-10-12.** От Handy не отвязываемся: его исправления надёжности приходят бесплатно. Наш код живёт в наших модулях, в файлах Handy — только тонкие точки подключения (эта таблица). Вливаем перед каждым выпуском или раз в 2–4 недели. Обоснование — план рефакторинга (в частной папке проекта).

Последнее вливание: 5 коммитов Handy до `14ae9c6` (2026-10-13). Запись с микрофона переехала в отдельную библиотеку `handy-recorder`, поиск речи (VAD Silero v6) теперь считает transcribe.cpp вместо ONNX, transcribe-cpp обновлён до 0.4.0, в пост-обработке «свой сервер» может работать в формате Anthropic. Наши добавки этих мест почти не касаются: запись с микрофона и VAD мы не меняли, расшифровка файлов VAD не использует. Конфликтов было семь: `Cargo.toml` (их `handy-recorder` и новый `rodio`, наши фичи `tokio` и `multipart`), `Cargo.lock` (взят их и пересобран), `actions.rs` (наши сообщения оверлея о сбое микрофона теперь берут вид сбоя из их `recording_error_type()`), `llm_client.rs` (их правило «обрезанный по лимиту ответ — ошибка» оставлено для диктовки внутри нашей обёртки, расшифровка файлов по-прежнему получает признак обрезки), удалённая нами `PostProcessingSettings.tsx` (оставлена удалённой), переводы en/ru (оба ключа). Проверка — §9.11.

Предыдущее вливание: Handy после 0.9.8 (6 коммитов до `48a3d8e`, 2026-10-12). Главное из них — распознавание transcribe.cpp (Whisper, Parakeet в формате GGUF) работает в отдельном процессе-работнике (тот же `handy.exe` с особым ключом), поэтому сбой или зависание движка больше не роняет программу. Конфликтов было пять: `lib.rs` (новый модуль рядом с нашим; при выходе из программы теперь останавливается только встроенная нейросеть — работник распознавания закрывается сам), `managers/transcription.rs` (`loaded_model_is_whisper()` и «только процессор» переписаны на новый движок), `RecordingOverlay.tsx` (наше состояние «модель занята файлом» рядом с их «Загрузка модели…»), переводы en/ru. Проверка — §9.9.

Прежнее вливание: Handy 0.9.8 (17 коммитов, 2026-10-05), два тривиальных конфликта (`tauri.conf.json`, импорт в `settingsStore.ts`).

### Публичный репозиторий: чистый снимок

Публичный репозиторий `PereverzevVV/tishe` начинается не с нашей истории, а с одного коммита поверх истории Handy: в старых коммитах есть личная почта и пути. Работа по-прежнему идёт в ветке `handy-plus` со всеми рабочими материалами. Для выпуска есть отдельная ветка `public-release` (своя папка через `git worktree`): это `handy-plus` плюс один коммит, который убирает то, что не публикуется (§5.25). В публичный репозиторий уходит только её содержимое, одним коммитом-снимком. Родитель первого снимка — последний влитый коммит Handy (`14ae9c6`), следующих — предыдущий публичный коммит. В PowerShell, в папке ветки `public-release`, без незакоммиченных правок:

```
git fetch origin
$d = Get-Date -Format yyyy-MM-dd
$env:GIT_AUTHOR_NAME = "PereverzevVV"; $env:GIT_AUTHOR_EMAIL = "PereverzevVV@users.noreply.github.com"
$env:GIT_COMMITTER_NAME = $env:GIT_AUTHOR_NAME; $env:GIT_COMMITTER_EMAIL = $env:GIT_AUTHOR_EMAIL
git remote add public https://github.com/PereverzevVV/tishe.git   # один раз

# первый выпуск: родитель — последний влитый коммит Handy
$base = git merge-base public-release origin/main
$snap = git commit-tree "public-release^{tree}" -p $base -m "Tishe: public release $d"
git diff public-release $snap --stat                   # должно быть пусто
git push public "${snap}:refs/heads/main" --force     # только в первый раз: заменяет стартовый коммит GitHub (LICENSE и README)

# следующие выпуски: сначала перенести уборку на свежую рабочую ветку
git rebase handy-plus                                  # конфликты «изменено — удалено» решаются удалением
git fetch public
$snap = git commit-tree "public-release^{tree}" -p public/main -m "Tishe: release $d"
git push public "${snap}:refs/heads/main"
```

Сборок GitHub в публичном репозитории нет (§5.25), поэтому на пуш ничего не запускается. Чтобы почта не попадала в коммиты на GitHub, там же включить «Settings → Emails → Keep my email addresses private».

### Протокол скрипта событий

Скрипт получает одну строку JSON в stdin на каждое событие, по одному запуску на событие:

```json
{
  "version": 1,
  "app": "tishe",
  "event": "progress",
  "job_id": "1790701283000-1234",
  "file": "D:\\rec\\lecture.mp4",
  "stage": "transcribing",
  "part": 2,
  "total_parts": 3,
  "fraction": 0.47,
  "elapsed_secs": 840,
  "eta_secs": 720,
  "message": "Распознавание: часть 2 из 3 · 47% · осталось ~12 мин"
}
```

- `event`: `started`, `progress`, `finished`, `failed`, `cancelled`, `test`.
- `app` — `"tishe"` (до выпуска 2026-10-15 было `"handy-plus"`).
- Всегда есть `version`, `app`, `event`, `job_id` (общий у событий одного файла), `file`, `elapsed_secs`, `message`.
- `progress`: `stage`, `part`, `total_parts`, `fraction`, `eta_secs` (после 15% и 30 с).
- `finished`: `output_path`, `characters`, `warnings`. `failed`: `error`.
- `.ps1` запускается через `powershell -NoProfile -ExecutionPolicy Bypass -File`, остальное — напрямую, без окна консоли. Тайм-аут 10 с.

Полная таблица полей — в `examples/event-scripts/README.md`.

## 8. Сборка, запуск для разработки, тесты

### Окружение (Windows)

Установлено через winget: Rust (rustup, stable-msvc), Bun, CMake, Vulkan SDK 1.4, Visual Studio 2022 Build Tools (C++), FFmpeg. Если в новой консоли команды не находятся, перезапустите терминал: winget обновляет `PATH` только для новых процессов. Перед первой сборкой нужна VAD-модель (с 2026-10-13 — Silero v6.2 в формате GGUF; файл лежит в репозитории Handy, отдельно скачивать не нужно, команда — на случай, если его нет):

```
curl -L -o src-tauri/resources/models/silero-vad-v6.2-F32.gguf https://huggingface.co/handy-computer/silero-vad-v6.2-gguf/resolve/main/silero-vad-v6.2-F32.gguf
```

### Установщик

```
bun install
powershell -ExecutionPolicy Bypass -File scripts/fetch-llama.ps1
powershell -ExecutionPolicy Bypass -File scripts/fetch-ffmpeg.ps1
bun run tauri build --bundles nsis
```

`fetch-llama.ps1` один раз скачивает зафиксированный релиз llama.cpp (`b11415`, CPU x64, 18 МБ) с GitHub, сверяет SHA-256 и раскладывает `llama-server.exe` с библиотеками в `src-tauri/llama-runtime/` (лишние утилиты не копируются). Без этой папки сборка Windows не пройдёт: она указана в ресурсах установщика. Чтобы обновить llama.cpp, поменяйте в скрипте `$Tag` и `$Sha256`.

`fetch-ffmpeg.ps1` один раз скачивает закреплённую сборку ffmpeg под LGPL (BtbN n8.1.3, zip 170 МБ), сверяет SHA-256 и кладёт в `src-tauri/ffmpeg-runtime/` только `ffmpeg.exe`, `LICENSE.txt` и `SOURCE.txt` (§5.25). Сначала он пробует копию в выпуске `build-deps` репозитория Tishe, потом BtbN. **Один раз после создания репозитория:** создайте на GitHub выпуск с тегом `build-deps`, отметьте его «pre-release» (иначе проверка версии примет его за последний выпуск) и приложите к нему `ffmpeg-n8.1.3-18-g46d899d7a0-win64-lgpl-8.1.zip` и исходники FFmpeg этого коммита (`https://github.com/FFmpeg/FFmpeg/archive/46d899d7a02bc63237472cc4897258d5ddf274ac.tar.gz`).

**Перед сборкой выпуска:**
1. В `src/lib/release.ts` поставить `TISHE_RELEASE` — дату выпуска (`2026.10.20`); тег выпуска на GitHub — `v2026.10.20`. Для предрелиза тег `v2026.10.20-pre` и галочка «Set as a pre-release» при публикации (§5.8).
2. Если менялись `Cargo.lock`, `bun.lock`, каталог моделей или сборки llama.cpp и ffmpeg — перегенерировать лицензии: `bun scripts/notices/gen-notices.ts` (нужны `cargo install cargo-about --locked --features cli` и `bun install`) и закоммитить `src-tauri/licenses/THIRD_PARTY_NOTICES.txt`.

Результат: `src-tauri/target/release/bundle/nsis/Tishe_0.9.8_x64-setup.exe` (до 2026-10-09 — `Handy Plus_…`). Первая сборка занимает ~20 мин, повторная ~10 мин (LTO).

### Разработка

```
bun run tauri dev
```

Чтобы dev-версия не делила данные и горячую клавишу с установленной, её запускали с отдельным идентификатором:

```
set TAURI_DEV_HOST=127.0.0.1
bun run tauri dev --config "{\"identifier\":\"com.handyplus.dev\",\"build\":{\"devUrl\":\"http://127.0.0.1:1420\"}}"
```

(`127.0.0.1` вместо `localhost`: иначе Tauri на этой машине не дожидался Vite.)

2026-10-09 порты 1333–1432 оказались в зарезервированном диапазоне Windows (`netsh int ipv4 show excludedportrange protocol=tcp`), и Vite падал с `EACCES` на 1420. Тогда сервер переносится на другой порт, а `TAURI_DEV_HOST` не задаётся (иначе Vite занимает ещё и 1421):

```
bun run tauri dev --config "{\"identifier\":\"com.handyplus.dev\",\"build\":{\"devUrl\":\"http://127.0.0.1:1620\",\"beforeDevCommand\":\"bun run dev --port 1620 --host 127.0.0.1\"}}"
```

Окно можно проверять через удалённую отладку WebView2: перед запуском `set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`, затем протокол CDP на `http://127.0.0.1:9333/json`.

### Тесты

```
cd src-tauri
cargo test --lib file_transcription
```

Юнит-тесты (45 шт. на 2026-10-12). Пронумерованные строки: нарезка, разбор ответа, откат строки по каждой причине, номера вне куска; обработанные абзацы сохраняют спикера и время. Язык по тексту, а не по настройке; заминки ru/en и слова, которые не трогаются; склеенная пунктуация; распознавание перевода; встроенные инструкции совпадают с прежними. Раздел «Замечания обработки»: время этапов, по частям, предупреждения. Разделение по говорящим: окна покрывают файл, склейка и чистка реплик, кластеризация, поглощение мелких групп, известное число людей при постороннем обрывке, отрезки по репликам, метки в документе, спикер облачного сегмента по перекрытию. Остальное: разбор тайм-кодов ffmpeg, формат `чч:мм:сс`, покрытие и границы отрезков, разрез в паузе, детектор тишины, разбивка по предложениям, точка на стыке отрезков, группировка абзацев, деление длинного отрезка на абзацы,  скрипт событий: текст `message`, оценка оставшегося времени, троттлинг прогресса, формат JSON.

Тесты интерфейса из Handy (Playwright, юнит-тесты `*.test.ts`) и сборки GitHub в публичный репозиторий не входят (§5.25).

Поиск неиспользуемого кода: `bun x knip@5` для интерфейса и `cargo machete` (ставится через `cargo install cargo-machete`) для Rust. Ложные срабатывания knip: окошко диктовки `src/overlay/*` (это второй вход через `src/overlay/index.html`, knip его не видит), файлы в `src-tauri/target` и `.nix`.

Интеграционный тест на реальных медиафайлах и ffmpeg, с мок-сервером API:

```
set HANDY_FT_MEDIA_DIR=<папка с short.webm, short.mp4, short.mp3, long.mkv>
set HANDY_FT_MOCK_URL=http://127.0.0.1:8765/v1
cargo test --lib media_pipeline -- --ignored --nocapture
```

Разделение по говорящим на реальном файле (печатает реплики и время; в сборке `--release` время честное):

```
set HANDY_DIAR_MEDIA=<аудио или видео>
set HANDY_DIAR_MODELS=<папка с model.onnx и wespeaker_en_voxceleb_resnet34.onnx>
cargo test --release --lib diarize_media -- --ignored --nocapture
```

`HANDY_DIAR_SPEAKERS=2` задаёт число людей, `HANDY_DIAR_EMBEDDING=<файл>` — другую модель голосов.

**Чтение разных форматов** (чек-лист Г выпуска): все файлы папки проходят те же шаги, с которых начинается расшифровка, — определение длины, извлечение звука, кусок MP3. Файлы с именем `bad-…` должны дать ошибку, остальные — звук той же длины, что в заголовке. Сюда удобно класть настоящие записи: m4a с телефона, mp4 из Zoom, голосовые из Telegram, webm из браузера.

```
set TISHE_MEDIA_DIR=<папка с файлами>
cargo test --lib media_formats -- --ignored --nocapture
```

Проверки кода: `bun x tsc --noEmit`, `bun x eslint src`, `cargo fmt --check`, `cargo clippy`.

Переводы: `bun run check:translations` — у каждого из 25 языков есть все ключи английского файла, а у ключей с числом — все формы множественного числа этого языка (§5.24). Новые строки интерфейса добавляются во все 26 файлов `src/i18n/locales/*/translation.json`, а не только в русский и английский.

2. Ответ, обрезанный по лимиту токенов (`finish_reason = length`), принимается как полный. Последняя строка такого ответа — обрубок на полуслове. Так обрываются и 4 строки с потерей 7–8%, которых первое правило не видит. Последнюю строку обрезанного ответа надо оставлять исходной.

## 10. Ограничения и известные особенности

- **Зациклившийся отрезок теряет хвост.** Если модель (так бывает с Qwen3-ASR 1.7B) начала повторять одно и то же, transcribe-cpp останавливает этот отрезок; Tishe берёт то, что успело распознаться до повтора, и идёт дальше. Слова после места зацикливания в этом отрезке (до 25 с) теряются; в журнале — строка «Decode stopped early». До 2026-10-14 такая остановка прерывала весь файл (§9.14).

- **Переводы на 24 языка (кроме русского и английского) сделаны нейросетью** и носителями не вычитаны. Смысл и тон сверены со строками Handy этих языков, но отдельные формулировки могут звучать неестественно, а длинные составные слова (немецкий, нидерландский) — не помещаться в узкие кнопки. Описания моделей распознавания, которые приходят из каталога Handy, остаются на английском; установщик — тоже.

- **Уведомления Windows** реагируют на нажатие, только пока программа работает: уведомление из центра уведомлений после выхода ничего не откроет. В режиме «Не беспокоить» Windows кладёт их в центр уведомлений без всплывающего окна. В dev-сборке они подписаны «Windows PowerShell».
- **«Клавиша занята»** определяется только в экспериментальном режиме системных сочетаний; в обычном режиме (handy-keys) другая программа с той же клавишей сработает вместе с диктовкой, и это не видно.
- **Сообщения оверлея «Не удалось вставить», «Микрофон не найден», «Нет доступа к микрофону»** проверены показом самого сообщения и кнопкой «Что делать», но не настоящим сбоем: сбой вставки и отсутствие микрофона на этом компьютере не воспроизвести.
- **Онбординг**: экран языка и каталог проверены в предпросмотре; настоящее скачивание с нуля на чистых настройках не проверялось (модели на этом компьютере уже есть).
- **«Быстрый старт» хранится в данных окна** (`localStorage` WebView2), а не в настройках. Если эти данные очистить, список больше не появится — модели, настройки и история при этом не теряются. Шаг «Попробуйте диктовку» засчитывается по первой записи в «Истории»: если история выключена или очищена, его можно закрыть кнопкой «Скрыть».
- Установщик Tishe удаляет Handy Plus только если тот стоит в папке, имя которой кончается на «Handy Plus» (так ставит установщик по умолчанию); иначе удаляет только его запись в списке программ и ярлыки, а папку оставляет.
- Описания моделей распознавания в каталоге приходят из каталога Handy на английском.
- **«Осталось» при расшифровке** считается по средним скоростям этапов (§5.23). Для встроенной нейросети взята скорость Gemma 4 E4B: с Gemma E2B оценка будет завышена примерно вдвое, с Qwen3.5 9B — занижена. Короткая запись (до ~4 мин речи) уходит нейросети одним куском, и полоса стоит на месте, пока он не вернётся.

- **Окно ⚙ «Параметры»**: вариант сжатия и язык модели распознавания пока не настраиваются (§5.21). Параметры встроенной нейросети действуют на файлы; температура, контекст, лимит и потоки — и на пост-обработку диктовки, потому что это параметры запуска сервера.

- **Формат Anthropic для своего сервера** (появился в Handy 2026-10-13) на странице «Редактура» пока не выбирается: страницу Handy, где он был, заменила наша. Встроенный поставщик Anthropic работает как раньше; расшифровка файлов обращается к нему по OpenAI-совместимому адресу `/chat/completions`, а диктовка — по родному `/messages`.

- **Облачное распознавание и LLM проверены на мок-сервере**, повторяющем протокол OpenAI. С реальными ключами первый запуск стоит сделать на коротком файле.
- **Модель распознавания одна на диктовку и расшифровку** (в Handy одна активная модель). Поэтому на «Расшифровке» её нельзя выбрать: там строка «Распознавание: … · общая с диктовкой · Изменить», а меняется модель на «Моделях» или в строке состояния. Во время расшифровки смена модели заблокирована.
- **Диктовка во время локальной расшифровки файла** может не сработать: модель занята.
- Облачные модели `gpt-4o-*` не возвращают тайм-коды сегментов, поэтому их текст делится на абзацы по предложениям, без тайм-кодов.
- **Говорящие** безымянные («Спикер 1», «Спикер 2»).
- Встроенная модель путается, когда люди перебивают друг друга или у них похожие голоса.
- Короткие реплики меньше секунды («да», «угу») приписываются соседней реплике.
- В автоматическом режиме иногда появляется лишний «спикер» из нескольких секунд (кашель, смех, другой микрофон). Если число людей известно, укажите его.
- Подбор параметров шёл на искусственных диалогах из лекций; на живых совещаниях с перебиваниями точность будет ниже. Проверьте на своих записях.
- С облачными моделями без тайм-кодов (`gpt-4o-transcribe`, `gpt-4o-mini-transcribe`) разделение по говорящим не работает.
- **Локальная нейросеть работает только на процессоре** и заметно медленнее облака (§3.1). Встроенный поставщик есть только в сборке для Windows.
- GigaChat 3.1 и Qwen3.5 9B при разработке не скачивались и не замерялись: их скорость и память в §3.1 — оценка.
- Семь моделей с ускорителем (§3.1) добавлены без замера: шкалы скорости и качества у них — оценка. На короткой фразе ускоритель Gemma выигрыша не дал (§3.1). LFM2.5 8B-A1B и MiniCPM5 2B не заявляют русский язык.
- При отмене во время обработки локальной нейросетью текущий кусок дорабатывается в фоне (до ~1 мин), затем процесс простаивает и выгружается по обычным правилам.
- Если до обновления была выбрана папка сохранения, она осталась выбранной; вернуть «Рядом с исходным файлом» можно кнопкой сброса.
- **Новые версии не ставятся сами** (§5.8): программа только сообщает о выпуске и открывает его страницу, установщик скачивается вручную. Проверка сравнивает дату `TISHE_RELEASE` в сборке с тегом выпуска: если забыть поменять дату перед сборкой, уведомление будет неверным.
- **Кто выбирал Canary 1B** (некоммерческая лицензия, убрана из каталога): после обновления выбор модели сбрасывается на другую, а её файлы остаются на диске, и удалить их из программы нельзя — только вручную из папки моделей. Скорее всего, таких пользователей нет.
- **Установщик закрывает любой `handy.exe`** текущего пользователя, если в папке Tishe лежит старый `handy.exe`: с ним заодно закроется и оригинальный Handy, если он запущен (установщик спрашивает перед этим).
- **Переведены не все ошибки.** Частые ошибки расшифровки файла показываются на языке программы (§5.25), редкие технические — как есть, по-английски.
- **Установщик вырос примерно на 55 МБ** (оценка по архиву ffmpeg, §5.25): цена ffmpeg внутри. Своя урезанная сборка ffmpeg отложена.
- Установщик не подписан, SmartScreen предупреждает при установке.
- **Скрипт событий** работает только для «Расшифровки», не для диктовки. Оставшееся время — оценка (§5.12). Примеры скриптов не входят в установщик: их нужно взять из репозитория.
- С выпуска 2026-10-15 программа называется **Tishe** везде, кроме ветки `handy-plus`, файла журнала `handy.log` и внутреннего имени пакета Rust `handy`: их пользователь не видит, а переименование мешало бы слияниям с Handy.
- При первом запуске после переноса данных из Handy 0.9.6 один раз показывается окно «Новое в Handy v0.9.7». Это штатное окно Handy о новом поведении горячих клавиш; закройте его крестиком.

## 11. Решение проблем

| Симптом                                               | Что делать                                                                                                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Диктовка вставила старый текст из буфера обмена, а не продиктованный | Текст распознан и лежит в «Истории». Программа кладёт текст в буфер, нажимает Ctrl+V и через 60 мс возвращает прежний буфер; если окно, куда вставляют, читает буфер позже (бывает в первый раз), оно получает старый текст. Включите «Диктовка → Если что-то не работает → Надёжная вставка (бета)»: прежний буфер возвращается только после того, как окно прочитало текст. Или увеличьте там же «Задержку после вставки» до 150–300 мс |
| Красная плашка «Не найден ffmpeg»                     | В установщике ffmpeg есть: проверьте папку `ffmpeg` рядом с `tishe.exe` (антивирус мог её удалить) и переустановите Tishe. Запасной вариант — `winget install Gyan.FFmpeg` и перезапуск |
| После обновления пропали настройки, история или модели | Перенос из старой папки не прошёл (обычно старая версия ещё работала). Закройте все окна Tishe и `handy.exe` в диспетчере задач и запустите Tishe снова: перенос повторится. Старые данные — в `%APPDATA%\com.handyplus.app\`, подробности — в журнале, строки «Moved … user data» и «Could not move» |
| «Не удалось проверить обновления»                    | Нет интернета или GitHub недоступен. На работу программы не влияет; проверку можно выключить в «Приложение → Обновления» |
| Нет уведомления о готовой расшифровке                 | «Приложение → Уведомления» включено? Окно было на виду (тогда уведомления нет специально)? «Параметры Windows → Система → Уведомления»: разрешены для Tishe, выключен «Не беспокоить» |
| Значок в трее не виден                                | Windows прячет новые значки: перетащите его из скрытых значков (стрелка ^) на панель задач                                    |

| «Не выбрана модель распознавания» (раньше «no local model is selected») | Скачайте или выберите модель в разделе «Распознавание»                                                                             |
